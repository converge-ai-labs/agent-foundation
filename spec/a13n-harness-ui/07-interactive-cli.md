# Interactive CLI

## Design Position

Harness UI is a full-terminal client of `HarnessUiApp`. The App remains the sole owner of configuration acceptance, agent execution, continuation selection, decisions, agent cancellation, and agent observations. Explicit user-owned local shell commands are terminal operations, not agent executions. Terminal code does not construct Harness Runs, Environment mounts, or database transactions. The WebUI adapter reuses the same App boundary through the explicit `a13n-harness-ui webui` subcommand. Interactive mode does not start a server, daemon, or subprocess terminal. The CLI uses native prompt-toolkit interaction on Windows, macOS, and Linux: single-screen startup update confirmation and setup followed by one full-terminal conversation Application. These stages never compete for terminal input.

The terminal owns one current conversation and an editable draft. Durable Thread and Project identities remain internal application concepts. Removing their management UI does not delete or migrate historical execution data.

## Startup and Terminal Ownership

`a13n-harness-ui` without a subcommand starts interactive mode in the invocation's current directory. Input and output must both be terminals; automation uses `a13n-harness-ui run <prompt>`. CLI help, version, and command parsing do not import the App, Harness, database, provider libraries, or terminal renderer.

Startup mounts the landing TUI before heavy imports and App initialization. Loading, questions, account actions, and previews replace the current view in one alternate-screen Application, not append terminal scrollback. Setup releases the terminal before the conversation Application starts. It does not issue a model request, authenticate an account, launch an Environment, or connect configured MCP servers merely to inspect configuration. Ctrl+C exits preparation. A usable selected Agent and Model configuration enters the conversation directly; an unconfigured launch first opens the standalone setup workflow. Broken configuration produces repair guidance rather than overwriting the source. Startup failures return to the terminal without mounting chat. One task owns the same App context through setup, conversation, and cleanup; setup does not start a second App or an execution Run.

One process owns input and terminal rendering for its lifetime and restores the terminal on exit. A scrollable Markdown viewport retains a bounded semantic display cache, not a second conversation database. Blocks reflow on resize and theme changes. Eviction and truncation are visible; `/history` reads durable App history. Streaming updates are coalesced, and completed blocks are not reparsed on each delta. Large active messages use cached plain-text chunks until final Markdown reflow. Rendered rows are paged through disposable local caches, not deleted merely to satisfy a viewport budget. Semantic retention remains separately bounded and eviction is explicit. Interleaved root and child messages remain distinct. Finalization and cancellation flush pending text. Scrolling away from the latest output freezes the view until explicitly returning to the latest output. Best-effort event loss is distinguished from a complete live transcript; the committed final answer remains authoritative.

The composer, pending interaction, status, and transcript share one layout. Narrow or short terminals preserve usable input. Dark, light, and passive automatic themes are available; auto preserves the terminal default foreground/background and semantic ANSI palette. Terminal detection never consumes keyboard input. Theme colors apply consistently to transcript, composer, selections, and status. The bounded multiline composer has a distinct surface and contextual action hints; short terminals collapse decoration before sacrificing editable input. Scroll mode captures mouse events by default: the transcript, selector, and composer handle their own region. Selector wheel motion browses options without changing an answer; clicking highlights and Enter confirms. Ctrl+Space switches selector/composer keyboard focus; arrow keys edit the composer when it owns focus. Esc dismisses an interaction or completion before toggling scroll/select mode. Select mode leaves mouse selection/copy to the terminal, so application-local wheel routing is unavailable; PageUp/PageDown and Ctrl+End remain usable. Returning to the bottom resumes following output. Clipboard images are read only on an explicit paste action, with file attachment as a portable fallback. Multiline text paste never triggers image reads or submission.

Enter sends a new prompt while idle and sends text guidance to the active root operation while it accepts steering. During a pending decision or selector it answers that interaction instead. The composer identifies whether Enter sends a prompt, adds guidance, or confirms a selection. Alt+Enter inserts a newline; bracketed multiline paste remains a draft until explicit submission. Ctrl+C clears an idle draft or requests active cancellation. Ctrl+D on an empty draft exits. Rejected commands and unavailable submissions preserve input. Unknown slash input is never sent to a model.

Interactive logging writes JSON diagnostics to `<data-root>/logs/terminal.log`, with 5 MiB rotation and three backups, rather than either terminal screen. Repeated unchanged plugin diagnostics produce one actionable terminal notice per process; details remain in the log. Noninteractive and WebUI logging are unchanged.

Interactive launch and explicit setup check the public package index before configuration readiness and setup questions when `process.terminal_update_check` is true (the default). `--no-update-check` disables both cache lookup and network detection for one invocation; `make a13n-harness-ui` always supplies this flag. Development versions (`0.0.0` and PEP 440 development releases), help, version, and noninteractive commands never check. A daily metadata cache lives under the data root; the check has a three-second total timeout, a bounded response, no model credentials, and silent offline failure. Only stable PEP 440 versions newer than the installed distribution trigger a prompt.

The update prompt and subsequent setup redraw the same landing TUI. For a recognized uv-tool installation it shows the command and installation directory, with **Update now** and **Not now** choices; Not now is the default. Escape or Ctrl+C at the update question skips updating. Skipping is not remembered as installation consent or version suppression: a still-newer cached version prompts again on the next enabled launch. Unknown installation methods show manual package-manager guidance and cannot launch an installer.

Detection never installs anything. Only an explicit Update now answer returns an installer command to the executable. The App and terminal fully close before `uv tool upgrade a13n-harness-ui` inherits the ordinary terminal, using the running installation's uv tool directory. Success asks the user to restart; failure reports the installer exit status without retry. Neither path continues setup or chat in the old process, and no startup or exit task installs in the background. Exit does not repeat update notices.

After terminal restoration and App cleanup, an existing saved root session produces a shell-quoted `a13n-harness-ui --resume <thread-id>` hint with configuration/data-root overrides and the required workspace directory. Setup-only, failed startup, and sessions without a created thread have no resume hint. The hint does not assert that an unfinished Run published a continuation.

## Commands and Presentation

One command catalog owns syntax, aliases, help, completion, and availability during active work. Duplicate names or aliases are rejected. Commands that would change subsequent execution configuration are unavailable while work is active. `/mode`, `/status`, `/help`, `/steer`, `/cancel`, and `/quit` remain available. Command arguments preserve native backslashes; paths containing whitespace use surrounding quotes. `/result` takes a request ID followed by raw JSON, without shell quote removal.

- **Concise** is the default: assistant text, independently expanded provider-exposed reasoning, decisions, errors, tool identities, and folded previews for ordinary tool arguments/results. User messages use a prompt marker rather than a role-name prefix.
- `edit` and `multi_edit` show expanded diffs only from the successful native `a13n.filesystem.edit_applied` event's actual before/after text. Absolute file hunk positions, all replaced occurrences, and trailing-newline differences derive from that result. Failed batches and semantic no-ops produce no applied panel. Comparisons above a combined 131,072 characters or 2,000 newline boundaries use explicitly labeled actual before/after text instead of potentially quadratic diff matching; ordinary transcript retention bounds still apply. Invocation arguments remain ordinary folded previews, not an authoritative effect description.
- `summarize` shows the persisted summary and file reminders from `a13n.context.handoff_summary`, not a projection of its arguments. Handoff and compaction lifecycle blocks show every exposed field, including operation identity and failure phase. Preparation and application are distinct. Compaction summary content arrives through the public native Capability event, correlated by operation ID, and is displayed in a separate expanded Markdown block. The CLI never infers it from unrelated or previously selected history.
- **Detailed** expands retained ordinary tool blocks and additionally shows subsequent child output. Tool results identify their call and elapsed observation time; child output identifies its execution or Run. Neither mode invents reasoning or exposes hidden model state.
- `/mode concise|detailed` and Ctrl+O fold or expand retained tool details without deleting their sources. `/history` explicitly reads saved details independent of presentation mode. Upstream omissions and retention bounds remain visible, not represented as recoverable full content.

Display mode never changes tool access, shell review, model reasoning effort, or approval behavior. The compact status bar prioritizes state, model, reasoning effort, context occupancy percentage, and elapsed time. Occupancy uses the last root request footprint divided by the configured working budget, not provider capacity. Unknown usage is shown as `--`, real zero as `0%`. Narrow widths discard secondary fields before the current state. `/status` retains exact counters, model, environment, and session details. Request footprint is not cumulative Run usage and does not estimate the next prompt. Child and auxiliary request usage are not added to root context occupancy.

Active-run Enter captures the exact root receipt before asynchronous dispatch and sends literal text through the App's existing steering operation. `/steer <message>` remains an optional explicit entry point, not a prerequisite for guidance. Acceptance means the Harness accepted the input for a model boundary, not that the model consumed it or that a durable checkpoint exists. Native delivery observations are presented separately from acceptance. Preparation, cancellation, non-agent work, completed receipts, and absent receipts do not accept ordinary steering input. A draft containing images is preserved in full rather than silently sending only its text. A rejected or unconfirmed submission restores its draft or exposes `/recover` without overwriting a newer draft. A race with Run completion never converts guidance into a new prompt or retargets a replacement receipt. The CLI adds no next-Run queue, message reordering, or automatic retry; native Harness enqueue order and consumption boundaries remain authoritative.

### User-owned Local Shell

`!command` is reserved before steering and interaction dispatch. On an idle POSIX host it runs noninteractively in the CLI invocation directory with the inherited host environment. It is explicitly outside the model's selected Environment or Sandbox; the panel labels it **Local shell**. It does not create a Harness Run, invoke the model, inject output into model context, or consume attached images. Model shell tools continue through the selected Harness Environment.

Active work, preparation, and pending interactions reject the command while preserving its draft. Bare `!` shows usage. One foreground job owns process creation, both pipe readers, deadline, cancellation, and process-group cleanup. Native terminal operation events carry started, stdout/stderr output, and finished observations with phase, exit code, elapsed time, and truncation. Rendering consumes only these events. Output is bounded to a combined 256 KiB while excess bytes are drained; stdin is closed and the deadline is 120 seconds. Cancellation, timeout, and terminal exit kill the owned process group and await cleanup, including cancellation during creation. Commands cannot serve as detached terminal jobs. Windows rejects `!command` until equivalent lifetime cleanup is supported; this limitation does not disable the normal Windows CLI or model shell tools.

## Project Selection and Resume

The CLI is an entry point into the ordinary [Project model](04-projects-threads-and-environments.md#projects), not a separate Workspace resource. On the first submission, the App matches the canonical invocation directory against Project first roots. A unique exact match is reused with its entire ordered root list; additional roots do not make it ineligible. Without a match, the App publishes a deterministic directory-derived single-root Project through normal validated configuration mutation. Multiple exact matches require explicit session resume or a Project configuration edit, rather than silently choosing an ID or creating a duplicate. It does not adopt a containing ancestor or match a secondary root as an entry point.

CLI creation and resume use the same App-owned exact-first-root query. The CLI never rewrites or narrows Project roots. Setup also reuses a unique matching Project and preserves its resource instead of publishing a duplicate single-root starter; ambiguous matches require configuration repair before setup publication. Adding roots through configuration or another surface therefore preserves CLI Project identity and resumability from the first root. The first root remains the default working directory and subsequent Runs capture all configured roots; admitted Runs retain their existing capture. Concurrent creation can reuse a verified identical resource; collisions or unrelated configuration changes fail without overwriting user files.

Launch resume cannot be combined with Agent, Environment, or title overrides; the CLI rejects the combination before startup rather than silently discarding a requested permission boundary.

`/new` clears the current selection and starts a new conversation on the next submission, preserving all history. `/resume` lists saved root sessions from Projects whose first root equals the invocation directory, including multi-root Projects; `/resume <id>` and `--resume <id>` reject archived, child, active, and nonmatching-Project sessions. Resume uses the durable selected continuation, not discarded partial output. Failed navigation preserves attached images and command text. Asynchronous command failures never overwrite a newer draft; explicit recovery remains available. Successful navigation discards only the unchanged prior attachment draft. `/history [cursor]` reads bounded retained pages without maintaining a duplicate terminal transcript database.

## Per-operation Model Selection

`/model` selects a configured Model resource for subsequent operations. `/thinking` changes reasoning effort independently from display mode. These selections are local to the interactive session and are passed as detached `RunModelOverrides` values; they do not rewrite YAML or sticky Thread configuration. Selecting a model resets reasoning to that model's configured default. `default` clears the corresponding override.

The root coordinator copies options before scheduling execution. Composition capture selects the accepted resource generation at the existing capture boundary, validates the effective settings, and records the complete effective Model recipe before native construction. A receipt alone does not claim that capture has finished. Inheriting Markdown children receive the effective parent model; explicit child and auxiliary selections remain independent. Invalid selections fail without fallback. Previous immutable compositions remain unchanged.

Resume restores the last selected continuation's Model ID and reasoning effort for subsequent operations, resolving them against current accepted resources. It does not restore stale credential bytes or silently resurrect deleted resources.

## Setup and Context Management

When the selected Agent has no Model configuration, the CLI opens setup in its own alternate-screen view before creating a conversation composer. The normal path selects a connection (Codex subscription, Grok subscription, or an API-key route/reference), selects execution permissions, then reviews and explicitly saves the configuration. Existing compatible subscription accounts, including refreshable expired credentials, are reused without another login prompt. Missing accounts offer explicit sign-in, rediscovery, or configuration without login; unsupported or malformed stores offer repair guidance without replacing the store. Discovery never authenticates or refreshes credentials. The preview offers optional model/context/reasoning, shell-review, and additional-instruction customization. Subagent migration is separate through `/import`, not a required setup step.

Selectable steps accept arrow keys, numeric choices, or exact values; text fields retain explicit defaults. Esc revisits selections and Ctrl+C/Ctrl+D cancel the wizard. Cancelling an initial wizard returns to the command shell rather than opening unconfigured chat. Successful first-use setup enters chat; explicit `a13n-harness-ui setup` exits after completion or cancellation. Chat has no `/setup` command. Cancellation before publication writes no selected resource files and never undoes completed credential operations. Existing edits, stale previews, and partial publication follow the shared setup contract. Configuration values remain explicit editable fields, not opaque preset references.

Codex defaults to `openai-codex:gpt-5.6-sol`, high reasoning, and a 350,000-token working context budget. Optional setup customization offers:

| Choice   | Working budget | Meaning                                                                  |
| -------- | -------------: | ------------------------------------------------------------------------ |
| standard |        272,000 | Current catalog default; conservative local budget                       |
| balanced |        350,000 | Repository-work recommendation aligned with the reference YAACLI profile |
| extended |        872,000 | Current catalog maximum; not an account entitlement guarantee            |

The local budget does not change provider limits. Generated Model resources declare `model_characteristics.context_window`, `proactive_context_management_threshold: 0.65`, and `compact_threshold: 0.90`. They are captured and supplied through native `HarnessModelCharacteristics`. Generated coding Agents select the native runtime-context, handoff, and compaction capabilities. At 350,000 tokens the derived reminder and compaction thresholds are 227,500 and 315,000. Explicit capability policies can override their native derived defaults.

The last root request's reported usage controls the native thresholds; accumulated usage does not. Codex subscription requests do not receive an API `max_tokens` cap copied from YAACLI presets. Provider-specific settings remain subject to the supported model adapter and native subscription constraints.

## Multimodal Drafts

The CLI uses the [App's native multimodal input contract](05-runtime-subagents-and-surfaces.md#process-local-operations). It sends actual `BinaryContent`, never a local path disguised as image content. Image-only input is supported without inventing a user prompt.

The composer retains at most eight images, at most 10 MiB per image and 20 MiB in aggregate. PNG, JPEG, WebP, and GIF are accepted after decoding validation. Oversized or invalid images do not alter the draft. Attachment chips identify pending images and support explicit removal. Clipboard acquisition runs off the input loop, is fenced to its originating draft, and never inserts a late image into a submitted, cleared, or replaced draft. A failed pre-admission submission preserves text and images for explicit retry; once admitted, receipt recovery governs the outcome and the CLI does not automatically resend input.

## Decisions, Cancellation, and Recovery

Pending approvals and external results are presented using App-owned deferred request types. Individual terminal answers are local drafts until every request in the exact continuation batch has a response. Unknown IDs, mismatched kinds, invalid JSON, or stale continuations are rejected. Cancelling, exiting, or leaving setup never implies approval. Structured question results remain subject to the same App/Harness validation as other adapters. Complete numbered option labels and descriptions remain in the scrollable transcript even when the compact selector clips them.

Cancellation goes through the root receipt and waits for execution/environment cleanup. Exit cancels active work before closing the App in its owning task. Login cancellation uses the existing credential-store transaction boundary; a completed store write is not reported as rolled back. No cancellation retries a potentially side-effecting operation automatically.
