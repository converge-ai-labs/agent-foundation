# Workbench Interaction

## Design Position

This document owns the browser's default interaction flow, action placement, and feedback. [Overview](00-overview.md) owns the product boundary; [collaborative conversations](01-collaborative-conversations.md) and [Host computer sharing](02-host-computer-sharing.md) own state and operation semantics; [Harness WebUI design guidelines](06-design-guidelines.md) own visual presentation.

The UI calls a human-facing conversation a **Chat** across navigation, actions, search, settings, sharing, notifications, and accessibility labels, while Thread and protocol IDs keep their existing meanings. Controls use direct user-action labels (Log in, Log out, Save changes, Connect account, Reconnect).

### Localization

Harness WebUI owns its i18next runtime and catalogs; shared UI receives application-owned strings. All application-owned chrome—login/setup, navigation, Projects, Inbox, composer, Model/Thinking/Speed/Reasoning controls, transcript disclosures, usage analytics, sharing, files, terminals, Browser, voice, and settings—provides English, Simplified Chinese (`简体中文`), and Hindi (`हिन्दी`, keeping product terms Agent, Run, Thread, Session, and Skill in English).

- **Preference:** Viewers choose System, English, 简体中文, or हिन्दी at login/setup or in Preferences (browser-local, independent of server config and Console). System maps `en*` → English, `zh*` → Simplified Chinese, `hi*` → Hindi, falling back to English.
- **Live switching:** Switching updates UI text and document `lang` immediately without reloading, refetching, mutating config, or losing drafts, undo history, attachments, open panels/dialogs, Browser leases, or pending/uncertain receipts. Embedded MCP Apps receive the resolved locale via Host-context updates without remounting.
- **Verbatim values:** User/model content, authored titles, Project/resource names, identifiers, paths, commands, logs, currency codes, recorded amounts, and unknown backend/provider diagnostics stay verbatim.

## Appearance

Settings → Preferences → Appearance controls browser-local theme (Light default, Dark, or System), independent terminal theme (Follow theme default, Light, or Dark), and six integer font sizes applied before initial render across login, owner, and guest views:

| Region       | Default | Range   | Content                                                          |
| ------------ | ------- | ------- | ---------------------------------------------------------------- |
| Navigation   | 13px    | 12–16px | Projects, chats and settings navigation                          |
| Interface    | 14px    | 12–16px | Menus, forms, buttons, tool labels and metadata                  |
| Conversation | 15px    | 14–20px | User and assistant messages, thoughts, Markdown lists and tables |
| Composer     | 16px    | 14–20px | Message input text                                               |
| Code         | 12px    | 11–18px | Code blocks, raw JSON, logs, source editors and diffs            |
| Terminal     | 13px    | 11–20px | Terminal text and cell grid                                      |

Changes apply immediately in 1px steps with a static preview, per-region resets, and **Reset appearance** (restoring all defaults and Light theme while leaving language, credentials, sidebar width, and drafts intact). The browser stores `{version: 1, theme, terminalTheme, sizes: {...}}` under `a13n-harness-ui.appearance` (migrating legacy `a13n-harness-ui.theme` only when the new key is absent; invalid/unknown data falls back to defaults without overwriting; storage failures keep in-memory state with an inline note). Same-origin tabs apply storage updates without writing back. Appearance changes preserve editor state, undo history, terminal connections (remeasuring PTY only if controller), and conversation bottom-follow or visible message-block anchor.

## Coordinator Entry

- **Promotion and composer opt-in:** Ordinary project-bound roots (not active, archived, or pending-decision) offer one-way **Make Coordinator** in actions/details with confirmation. In the composer's **Chat options**, **Coordinate agents** (Coordinator) and **Goal** are independent choices; Coordinator stages private intent (requiring an available Project and promotion eligibility, locked during pending/unknown/preparing sends; never silently falling back to ordinary execution). New conversations create directly as Coordinators; existing roots promote before submission with separate completion boundaries. Confirmed Coordinators show a non-toggle identity.
- **Default for New chat:** **Settings → Chats → New chats → Coordinate agents by default** saves the instance setting `webui.coordinator_by_default` (default `false`). The WebUI preselects **Coordinate agents** for a fresh independent chat with an available Project. An explicit composer choice wins, and a restored draft keeps its saved choice or the default from when it was saved. Existing chats and owned workers keep their own behavior. The WebUI sends the resulting explicit creation intent using the [existing Coordinator creation contract](../04-projects-threads-and-environments.md#coordinator).
- **Owned workers:** A Coordinator's **New worker** opens the new-chat composer with its Project and a removable **Managed by - name** chip (locking Project selection until removed or created; permanent once created; unavailable/archived/mismatched owners block creation).
- **Worker disclosure:** Project and Recent navigation show a leading worker disclosure only for Coordinators with unarchived owned workers. The disclosure starts collapsed and fetches worker pages with `coordinator_thread_id` when expanded. A fresh active or selected worker can reveal the disclosure before the Coordinator's count refreshes. When the last unarchived worker is removed or archived, the disclosure and open worker section disappear; a later worker makes the disclosure available again in its collapsed state.
- **Navigation and controls:** An idle Coordinator with active workers shows a quiet trailing active-worker count, and Coordinator actions include **Pause/Enable automatic follow-up**. A Coordinator appears once among active rows while either it or any unarchived worker is active (progress spinner reflects only the Coordinator's own execution), returning to the unread rows only for its own unread state; workers do not carry unread state or promote their Coordinator into unread rows. Workers never appear as top-level recent/active rows; missing or archived owners stay anchored with Restore; search marks workers **Coordinator worker**.

## Delete Chat

Instance owners can choose **Delete chat** on ordinary root rows (Project lists, Archived, or chat details; disabled while active; absent on Live, Memory, and child conversations). Confirmation names the chat, explains permanent removal of its subagent history while retaining Project files and other chats, and submits the displayed metadata version once (disabling repeat submit/dismiss while pending; errors stay in dialog). Success clears local drafts and caches, refreshes navigation, and replaces a deleted selected chat with New chat in its Project ([deletion scope](../03-local-storage-and-recovery.md#permanent-thread-deletion)).

## Usage Analytics

The sidebar footer workspace menu opens **Usage** (`/usage`), also reachable from Project menus (**View usage**) and Thread usage details (**Open analytics**) with matching scope. URL state owns filters (default 30 UTC days, 7/30/90-day presets, custom up to 366 days; intersecting Project, searchable root Thread, and selected-model filters), grouping, ordering, and pagination.

The page shows estimated USD spend, total tokens (with input/output subtotals), model requests, a daily tokens/cost chart (pointer and keyboard inspectable), and a paginated Project/Thread/model breakdown with an expandable **Token details** toggle (input, output, cache, unknown-cost) and **About these estimates**. Compact K/M/B units expose full counts and precise values in tooltips/labels; unknown prices stay distinct from zero. Reads run on entry, filter change, and explicit Refresh, disclosing read timestamp and observation coverage ([consumption analytics](../03-local-storage-and-recovery.md#consumption-analytics)).

## Entry and Navigation

- **Display modes and sidebar:** The sidebar heading places a **Conversation display** menu (**Projects** default, or **Conversations** → **Recent** cross-Project list ordered by navigation touch time + Thread-ID tie-breaker) beside its plus action. **New**, **Search**, and **Inbox** lead the sidebar above Projects; the footer menu lists Settings, Usage, and Log out; Archived chats and Live open from Settings → Chats. Desktop sidebar resizes 200–360px (default 220px, keeping ≥480px for content; double-click resets) and collapses locally; Settings replaces chat navigation in the same sidebar/drawer.
- **New chat and setup:** Fresh installations open `/setup`; configured installations open New chat resuming the browser's single local-storage draft (text, attachment refs, creation ID, selections, unresolved creation/submission state; local file bytes stay tab-local so reload marks them unavailable for removal/reattachment). First Send creates the Thread with its retained ID, uploads files, syncs the draft, and submits once (locking creation choices until exact-identity reconciliation on uncertain outcomes; absence uses `thread_missing`). The authored message echoes into the transcript as soon as Send starts, stays readable through preparation and admission, and becomes the saved entry in place; New chat shows it in place of the greeting and Project choice until the chat opens. Meanwhile the composer keeps its size and shows one quiet sending line instead of the same text. Only rejected or unconfirmed input stays in the composer with its recovery controls.
- **Model, Thinking, Speed, Reasoning, and Environments:** The composer right-aligns the Model + thinking trigger opening the **Agent & Model** popover (bottom sheet on mobile) with Agent, Model (searchable), Thinking (stepped track + Model default via [control descriptor](../02-agent-composition-and-snapshots.md#model-aware-thinking-controls)), Speed (Model default, Standard, Fast, Ultrafast via [Fast descriptor](../02-agent-composition-and-snapshots.md#fast-request-controls)), and Reasoning mode (Default, Standard, Pro via [descriptor](../02-agent-composition-and-snapshots.md#reasoning-mode-controls)). Changing Agent or Model clears dependent overrides; invalid choices stay explicit until reset; Send captures overrides atomically (steering excludes them); Debug shows captured active-Run settings separately. **Chat options** groups Goal, Worktree, Coordinate agents, Environments (following [Device and Environment binding selection](../04a-devices-and-environment-bindings.md#webui-behavior)), and eligible **Clear context**.
- **Search:** **Search** opens the global paginated chat search. Arrow keys navigate, Enter opens, and Escape restores focus and resets the query. `/archived` searches and restores archived roots independently.
- **Groups, drag reordering, and Inbox:** Each expanded Project group lists all active roots, then all unread roots, then up to 5 read-history rows (stars first, **Show more/less**), without bucket captions; each row shows one trailing mark in the order live state, active worker count, unread badge, star. Groups load via `include_active=true&include_starred=true` with navigation touch sorting. Project headings preview paths/counts on hover/focus, support quick rename, and reorder by drag or `Alt+Space` + arrows (default order puts Projects matching server cwd first). Ordinary roots reorder within their priority group (`Alt+Up/Down` or drag) and drag onto another available Project to transfer association (Coordinators/workers excluded). **Inbox** (`/inbox`) lists items newest first under **Open** (**Needs you** then **Updates**) and **Done** (Done implies read; `post_to_inbox` renders as a compact Inbox card in the transcript; **Open in chat** jumps via `?inbox=<item_id>` to the posting turn; **Settings → Chats → Inbox** controls [agent posting and automatic reading](../01-configuration-and-resource-catalog.md#inbox)). Thread rows show a quiet trailing pencil mark for [unsent shared input](01-collaborative-conversations.md#unsent-input-discovery). Workers nest under their owner at the same label inset beside a light section line, and **More workers** matches **Show more**. Row menus expose Rename, Share, Details, Archive/Restore (direct archive without confirmation).

Each Open Inbox section has two icon actions with accessible names and tooltips. **Mark all as read** clears unread marks; **Mark all as done** moves the section's Open items to Done, including items that were already read. Both actions cover all pages of the selected section and preserve the other section.

### Inbox in chats

In owner chats, **Sent to Inbox** cards show an unread dot or a quiet **Done** label. Once a card has a saved Inbox item, its header offers **Mark as read** / **Mark as unread** and **Mark as done** / **Move back to Open**. Done cards omit the read toggle. Reading leaves items Open; card errors stay inline. Inbox updates refresh the card state and sidebar count across tabs. Shared views do not fetch Inbox state or show its indicators or actions.

**Automatically mark Inbox items as read in chats** is on by default. A visible, focused chat at the bottom of its latest saved output reads observed items. A transcript post becomes eligible when its saved result or later saved output is in view; MCP posts are eligible without a transcript result. Historical and unfocused views retain unread items. Marking a card unread manually excludes it from this automatic visibility rule for the rest of the chat view.

An accepted owner prompt, steer or decision response also reads prior Inbox items in that chat, including posts without a transcript card. These rules apply to ordinary chats, Coordinators and Bot. Turning off automatic reading disables both rules. **Open in chat** and the notification’s **View message** still mark the explicitly opened item read.

### Shared Conversation Stars

Independent roots and Coordinators offer **Star/Unstar conversation** in their row menu (starred rows show a quiet filled mark noting stars are shared). Activation never navigates or confirms; errors stay inline without silent retry. Within read history, all starred rows load and precede unstarred rows in touch-time order. Application confirmations use styled dialogs rather than native browser dialogs.

## Workbench Keyboard Shortcuts

**Settings → Chats → Keyboard shortcuts** edits `webui.shortcuts` in the instance root YAML. The accepted values apply to the owner workbench across browsers; owner status exposes the mapping, with omitted fields interpreted as defaults. Guest shares do not receive these bindings. The separate `webui.send_shortcut` setting continues to control composer submission.

| Action                             | YAML field                | Default         | Other values           |
| ---------------------------------- | ------------------------- | --------------- | ---------------------- |
| New chat                           | `new_chat`                | `off`           | `mod-shift-o`, `mod-n` |
| Search chats                       | `search_chats`            | `mod-f`         | `mod-k`, `both`, `off` |
| Toggle navigation                  | `toggle_sidebar`          | `off`           | `mod-b`, `mod-shift-s` |
| Toggle supporting panel            | `toggle_supporting_panel` | `off`           | `mod-j`                |
| Open Files                         | `open_files`              | `off`           | `mod-shift-e`          |
| Open Changes                       | `open_changes`            | `off`           | `mod-shift-g`          |
| Toggle Terminal / create a session | `terminal`                | `ctrl-backtick` | `off`                  |
| Open Settings                      | `open_settings`           | `off`           | `mod-comma`            |

`mod` is Command on Apple platforms and Control elsewhere. `both` enables both Search shortcuts. New chat follows the **New** link or focuses the composer on the existing `/` or `/new` route. The navigation toggle collapses the desktop sidebar or opens/closes the narrow navigation sheet. Supporting-panel shortcuts apply on workspace routes when the target is available; Files requires Host file sharing and Changes additionally requires Host Git. The Settings shortcut opens `/settings` or returns to the last chat from within Settings. Browser-reserved combinations (such as New window in regular tabs or Command+comma in macOS browsers) depend on the window's ability to deliver the keystroke.

Workbench shortcuts ignore handled, composing, and repeating keys. An open dialog owns keyboard focus; the search and navigation bindings may refocus or close their own dialogs, respectively. Search leaves both keys to local find surfaces. A focused Host Browser screen or Terminal receives its own keys, except the enabled capture-phase Terminal toggle/create chords.

## Shared Unread Conversations

Read/unread state belongs to the trusted instance and is shared across owner browsers for independent roots, Coordinators, and visible Bot text publications (Coordinator workers are excluded and never carry unread state or offer **Mark unread**; guests stay read-only).

- **State and mutations:** SQLite stores one boolean and monotonic `read_state_version` per Thread (constant storage per conversation). A successful independent root or Coordinator completion sets unread atomically with [saved root completions](../03-local-storage-and-recovery.md#saved-root-completions), while Coordinator worker completions retain completion markers without marking unread; Bot sets unread and advances `read_state_version` on each visible assistant publication. Row menus offer **Mark unread** on independent roots and Coordinators (advancing `read_state_version` to fence stale read reports; Coordinator workers reject manual unread marks).
- **Automatic read and Mark all read:** Automatic clearing requires the saved transcript rendered in a visible, focused document scrolled to the bottom, sending exact `(completion_version, read_state_version)`. Group menus offer **Mark all read** (batches up to 100 non-archived unread non-worker Threads, capturing both versions at activation).

## Update Notices

On stable installations, the WebUI listener checks public PyPI and GitHub metadata when [update detection](../01-configuration-and-resource-catalog.md) is enabled. A release must have a non-yanked stable PyPI distribution and a published, non-draft, non-prerelease GitHub Release under the matching `release/a13n-harness-ui-v<version>` tag. Compare the highest verified version with the installed version using PEP 440. Security notices match published, non-withdrawn high or critical GitHub repository advisories for the `a13n-harness-ui` pip package whose affected range includes the installed version.

Both sources use public HTTPS requests with a ten-second fetch deadline and a 2 MiB per-response limit. Requests carry no installed version, credentials, or telemetry. The process loads the atomic `<data-root>/cache/update-notices.json` cache at launch and refreshes each source independently 24 hours after its last successful check. Failures retain the last successful value and retry after one hour. Advisory matches are specific to the version checked. Terminal startup shares the release entry.

Owner-authenticated `GET /api/update-notices` returns the current snapshot without outbound I/O. It contains the installed version, the optional latest stable release and whether it is newer, applicable security advisories, and the recognized install method (`uv_tool` or `other`). Shared viewers cannot read notices. Disabled checks and source, prerelease, or development builds expose the installed version and install method with empty notices.

The workspace menu trigger, its **Settings** item, and the **Diagnostics** navigation row show a quiet indicator for an unread release or visible advisory. An advisory takes warning priority over a release. **Settings → Diagnostics → About** shows the installed version and connection state, release link, and applicable advisories. A recognized uv-tool installation offers a copyable `a13n-harness-ui update` command to run after stopping Harness UI; other installations update through their original package manager. Browser-local dismissal hides a release's indicators while preserving its link. Advisory dismissal applies to the installed version and the advisory's update timestamp, severity, and summary. A newer release or changed advisory revision appears again.

## Feedback Placement

App-wide connection, configuration, and result-tracking notices share one compact top banner; global disconnection suppresses duplicate network notices in dependent views. Missing/inaccessible Threads show one unavailable state with Retry and New chat. In available conversations, live connection/replay handshakes stay quiet for 1.5s before showing status in the Activity/usage row. Actionable recovery feedback (read failures, draft sync, rejected sends, uncertain outcomes, stop recovery) has one home directly above the composer, retaining explicit recovery controls until resolved.

## Task Notifications

- **Audience and scope:** Browser-local audience selects **Entire workspace** (default) or **My runs only** (matching a random origin-scoped browser profile ID attached at submission). Browser-local scope selects **All** (default), **Bot only**, or **Inbox only**, applying to both in-app notices and Web Push.
- **Run eligibility:** [Root settlement](../05-runtime-subagents-and-surfaces.md#http-adapter-contract) omits in-app and Web Push notices for Coordinator worker completions, including Goal completions. Worker suspensions and failures remain eligible; worker status refresh and Coordinator follow-up still apply.
- **In-app notices:** Consumed from App-wide summary realtime; suppressed in-app when the route already views that conversation (still entering deduplication). Bot publications show **New message from Bot**; suspended Bot ops show **Bot needs your response**; Inbox items show **New in Inbox** (Needs-you stays until dismissed); eligible Goal completions emit `goal_verified` or `goal_incomplete`.
- **Web Push:** System notifications use one path: server Web Push → notification-only Service Worker (`/sw.js`). Opt-in requires an explicit Settings action (iOS/iPadOS 16.4+ tabs explain Add to Home Screen). Active pages report activity immediately on startup/visible return/setup and every ~60s; recipient selection targets subscriptions with `last_active_at` within the last 6 hours. Endpoints: `GET /api/push/configuration` (public VAPID key), `PUT /api/push/subscription`, `DELETE /api/push/subscriptions/{subscription_id}`, `POST /api/push/subscriptions/{subscription_id}/activity`, and `POST /api/push/subscriptions/{subscription_id}/test`. Server uses a bounded in-memory queue, encrypted Web Push, persisted VAPID identity, no redirects, and up to 2 attempts for transient failures ([local storage](../03-local-storage-and-recovery.md#browser-push-subscriptions)).

## Conversation and Shared Composer

- **Title generation:** New chats asynchronously generate a title from the first admitted human submission using `chat_title_model` or the chat Model; manual rename wins. Text, selected Skills, and attachments can each supply title context. Both title paths use attachment names, up to four thumbnails for an image-capable Model, and optional untrusted HTML title/description hints from up to three links. Hint requests omit authentication and cookies and check the Run's allowed hosts on every request and redirect. **Rename chat → Generate title** previews an editable title from the earliest two and latest 24 eligible history excerpts, including assistant replies. Sampling takes both ends of each excerpt within a shared 2,000-word budget and up to 200 words per assistant message. Tool activity, thinking, and system context are excluded.
- **Voice dictation:** Instance-key users can dictate into the draft or **Add to chat** comment via Codex subscription dictation or an audio-input Model ([Dictation](../01-configuration-and-resource-catalog.md#dictation)); dictation inserts final text at the caret without auto-submitting.
- **Reply annotations and Clear context:** Selecting assistant prose offers **Add to chat** with an optional comment (persisted per tab/Thread across reloads; submitted with Send/Steer). Saved chats expose **Clear context** in **Chat options** (confirming selected continuation via [explicit context-clearing command](../05-runtime-subagents-and-surfaces.md#detached-surface-contracts); disabled while active/preparing/unknown).
- **Observation, history, and input rail:** The workbench subscribes focused live channels only for the currently viewed root conversation and explicitly pinned resource owners over one multiplexed realtime transport, while retaining a bounded recent warm set for visited conversations (warming saved history once settled) and observing workspace-wide background activity through the summary channel. Switching to an active background conversation performs a snapshot-and-replay handshake without dropping output. Initial entry shows one loading surface until detail + first history page arrive. A left-edge input rail (popup on narrow screens) previews and jumps to ordinary inputs (512-char closing output preview), loading target history windows directly.
- **Execution stretches, tools, and questions:** Visible inputs and assistant prose stay in source order; execution stretches stay collapsed by default behind a single-line overview during active tool execution and behind **Worked** / **Worked for …** once settled (desktop inline reader capped at `min(256px, 42.67vh)` on demand; mobile full-screen modal). On desktop, while a trailing reasoning block streams non-empty text in an active running execution stretch (or settles with no running tool), a bounded `144px` live-scrolling thinking preview renders directly beneath the collapsed **Thinking** trigger (without pausing conversation following or duplicating the header), then collapses as soon as a tool call, subsequent visible content, or run completion arrives or when the viewer expands the work log; historical and inactive unfinished stretches stay collapsed without a preview, and mobile keeps its compact preview trigger without an inline thinking preview or auto-opened modal. Adjacent calls (up to 16) group under **Explored**, **Ran commands**, **Browsed the web**, **File changes**, **Tasks & notes**, **Subagents**, and **Tool executions**, exposing formatted/raw **Input & result** in ordinary mode (Debug adds IDs/envelopes). Inside an expanded work log or active subagent live output, reasoning collapses under **Thinking** / **Thought** (with `for Ns` when recorded), auto-opening and tailing incoming deltas for a trailing active reasoning block with non-empty text (pausing when the viewer scrolls up and resuming at the bottom) and collapsing to **Thought** once another step arrives or the active stretch ends while preserving explicit viewer open/collapse overrides. Questions (`ask_user_question`) render inline outside execution details and correlate by native tool-call ID. **File changes** renders before/after diffs from [tool presentation evidence](../03-local-storage-and-recovery.md#tool-presentation-evidence) with **Open on host** lookup when native files are enabled. Source-marked background notifications use [Activity](#activity) disclosures.
- **Message actions:** Submitted inputs and saved closing replies show local timestamps on hover/focus. **Copy** preserves the message text, including Markdown, and excludes attachments and generated filename placeholders. Messages without text omit **Copy**. Eligible replies offer **Branch in new chat**. Eligible sent inputs offer **Edit message**, including earlier inputs and the current fresh input during a Run. The editor preserves retained attachments and Skill text, and supports removing attachments. The checkmark or configured send shortcut submits directly in the same Thread; **Stop & send** waits for the active Run to settle. Cancel or Escape closes the editor without changing the Run. A failure keeps the edited input and an inline error. On success, the visible history and focused stream switch to the replacement without navigation. See [Edit a sent message](../04-projects-threads-and-environments.md#edit-a-sent-message).
- **Composer controls, shortcuts, and Skill completion:** Full-width editor above one action row (`Option+Left/Right` on macOS / `Ctrl+Left/Right` elsewhere uses Chinese word segmentation in CJK text). Typing `$` or `/` opens Skill completion inserting `$name ` (rendered as a brand-colored unit; validated per [interactive skill references](../02b-environment-skill-sources.md#interactive-skill-references)). One bottom-right primary action switches between Send (idle + input), Steer (active + input), and Stop (active + empty; targets captured receipt, never auto-retried). Confirmed failed roots offer **Retry** submitting `Continue completing the previous task.` as a new turn. Pending decisions remain compatible with Send/Continue (sending denies unanswered requests).
- **Send shortcut:** **Settings → Chats → Chat input** saves `webui.send_shortcut` (`enter` by default or `mod-enter`) in the instance root configuration source. The accepted value applies to owner and shared WebUI sessions when they read status or share access. With **Enter (default)**, `Enter` sends and `Shift+Enter` inserts a new line; the platform shortcut (`Cmd+Enter` on Apple devices, `Ctrl+Enter` elsewhere) also sends. With the platform shortcut selected, both `Enter` and `Shift+Enter` insert a new line. On touch-first devices (`pointer: coarse`), plain `Enter` inserts a new line in both modes, and a hardware keyboard can still send with the platform shortcut. When Skill completion shows candidates, plain `Enter` belongs to the picker. IME composition never triggers a send. The composer hint and accessible shortcut metadata follow the effective shortcuts.
- **Status strip and usage popovers:** One row above the composer shows Activity (left) and context tokens (`k` unit + occupancy ring + source breakdown when available) and combined model USD cost (right; opens cumulative usage popover with All / This chat / Subagents scopes). Bot shows this row in Debug mode only.
- **Scrolling and cutover:** Readers follow live output immediately while at bottom (upward scroll pauses following; top scroll loads earlier pages). Checkpoints suppress only the matching saved live prefix after history loads; Handoff/Compaction render as collapsible Summary disclosures.

### Composer input predictions

When enabled, the WebUI Host runs one background attempt via the [Harness post-run hook](../../a13n-harness/05-plugin-system.md#post-run-hooks-and-forked-inference) after an eligible root Run completes and releases its slot (no native tools; excludes Bot, memory, child, observation-only, and provider-managed stateful requests; usage attributed to `input_prediction`). Published `{continuation_id, text}` is stored in shared composer options and read via `POST /api/threads/{thread_id}/input-prediction`. The WebUI shows ghost text only in an idle, runnable, empty synchronized composer (Tab or accept button inserts as one undoable edit; Escape dismisses; Enter never accepts).

### Activity

**Activity** beside **Share** in the chat header shows running count and, for owner non-Bot chats with linked worktrees or external URLs, compact worktree and link indicators with counts. It toggles a floating card (Subagents and Tool calls, up to 3 rows each when present, followed by Tasks, Notes, Worktrees, and Links in order, up to 3 rows each, with **View all** opening `?native=subagents`, `?native=tools`, `?native=tasks`, `?native=notes`, `?native=worktrees`, or `?native=links` tabs in the supporting strip). Subagents show one row per child conversation (latest segment, deterministic glyph, Stop on hover/focus); Tool calls include `foreground_released=true` executions and read-only Shell observations. Activating a row or inline **Moved to background** opens a detail resource tab (read-only transcript/output, header Stop for children/tools). Chat details separates **Activity**, **Configuration**, and **Tasks & usage** tabs.

## Saved Output

Saved output is read-only. Markdown renders GFM tables, code blocks with copy, [static Mermaid previews](../../frontend/design-system.md#conversation-diagrams), and local KaTeX math (`$…$`, `\(…\)`, `$$…$$`, `\[…\]`, `math` fences; escape literal `$` as `\$`). Settled assistant replies offer the shared [HTML code preview](../../frontend/design-system.md#html-code-preview). Up to 8 same-instance native file links/images per message resolve near the viewport using authenticated [media preview](02-host-computer-sharing.md#content-and-mutations); external URLs stay plain links.

## Project and Resource Configuration

- **Settings structure:** Grouped into **Preferences** (Preferences, People & profile), **Workspace** (Chats, Agents, Bot, Models, Memory, Environments, Connections), and **Advanced** (Configuration files, Diagnostics). Single-value settings use horizontal name/value rows; long-form instructions use full-width editors.
- **Accounts, API keys, and Web providers:** **Accounts & API keys** separates Subscription accounts (grouped by provider with **Add account** for Codex, Grok, GitHub Copilot, ChatGPT; allowances/vouchers/credits separated; vouchers ordered by earliest expiry), Account groups (nested detail view), and API keys (grouped by referencing providers; secret values never read back). **Connections** includes Web provider accounts (search/scrape capabilities, pasted keys stored under references), MCP servers (explicit **Load/Refresh tools**, digest-checked **All tools** vs. **Selected tools**), Harness plugin instances, and [Connectors](../13-connectors.md) (shared dialog/bottom-sheet setup).
- **Models and Agents:** Models share one two-tab editor (**Connection** + **Model defaults** including `settings.openai_transport` WebSocket checkbox and preserved YAML comments). Agents group General, Tools & capabilities (including tool-search switch and per-MCP membership), Delegation (Agent children, Markdown children, instance roles), and Advanced, supporting inline Model creation.
- **Environments and Projects:** **Environments** groups Local execution, Devices, Profiles & extensions, Local runtime (`/settings/environments?tab=runtime`, [deferred local runtime setup](../06-setup-and-environment-readiness.md#deferred-local-runtime-setup)), and Browser (`/settings/environments?tab=browser`, [Host browser](../11-browser.md)). Project settings edits Roots, Agent, Environment, and Tools directly; **Apply Project defaults** / **Apply Project environments** previews before/after diffs and updates an existing Thread under its expected version. Inherited fields display Use default, Custom selection, or None ([whole-list replacement](../01-configuration-and-resource-catalog.md#global-defaults)).

## Thread Links

Owner non-Bot chats expose their [references](../04-projects-threads-and-environments.md#thread-links) inside **Activity**. When a chat has linked worktrees or external URLs, the chat header's **Activity** button displays compact worktree and link icons with counts alongside its running badge. Opening **Activity** lists **Tasks**, **Notes**, **Worktrees**, and **Links** in order (up to 3 rows each, with **View all** opening `?native=worktrees` or `?native=links` in the supporting panel). In Full Control with Host Git available, a default local root inside a linked Git worktree contributes a read-only implicit entry; an explicit link to the same canonical root uses the same row. Worktree rows show a branch, detached HEAD, or removed status when observed; supported actions open Changes, Files, or Terminal at the linked path. URL rows open the external target. Unlink removes the explicit reference without touching its target.

The owner-only `GET /api/threads/{thread_id}/links` returns navigation targets and best-effort status. `DELETE /api/threads/{thread_id}/links` removes an explicit reference by kind and target. The browser observes status for the open chat, with no sidebar probes or window-focus refresh. Scoped guest views do not render worktree or link indicators, sections, or routes.

GitHub pull requests, issues and discussions show artifact numbers and, when available, a title and state. Public GitHub REST reads work without credentials for pull requests and issues. Authentication comes from `GH_TOKEN` or `GITHUB_TOKEN` for GitHub.com, or the Host's `gh` login for the URL's host when computer sharing is enabled. Authenticated reads include private repositories, Enterprise instances and Discussions. GitHub observations are cached for 60 seconds; failures retain a previous observation or leave a static artifact display. Other URLs show their hostname and optional label.

**Worktree** is a one-send draft mode in Chat options when the selected Full Control Git project can use Host Git. It stages a hidden instruction to create and register an isolated worktree using repository conventions. It is an alternative to Goal and leaves Coordinator intent unchanged. Sending consumes the captured choice.

## Reading Code and Changes

- **Resource tabs and layouts:** Supporting pane holds one strip of user-opened tabs (New tab chooser for Files, Changes, Browser, Terminal; at most one Terminal and one Browser tab per workspace; private file buffers survive tab close). Dragging the split separator to the left switches to Tabs layout; dragging right collapses the pane. Narrow windows default to Tabs; phones show one view at a time.
- **Files:** Follows the selected chat's Project roots (first root default; breadcrumb folder menu switches roots; inline directory expansion; Reveal in Finder/Explorer when local; **Back to files** restores folder/filter/focus). Renders code with syntax highlighting, wrap, find, and go-to-line; Markdown opens in Preview; PDF/PPTX/spreadsheets/SVG render locally; unsupported types offer download. Moves require inspected revision and never overwrite existing entries.
- **Changes:** Groups staged, unstaged, and untracked files by repository with readable labels, optional ignored filter, and unified diffs (patch-line coordinates for capture; binary/conflicts explicit; **Add to prompt** captures reviewed selection into the shared draft). Refresh observes current checkout state; Git mutations run in Terminal.

## Terminal Interaction

Terminal lists sessions for the selected Project. The default [workbench binding](#workbench-keyboard-shortcuts) uses `` Ctrl+` `` to toggle/select Terminal and `` Ctrl+Shift+` `` to create a session in the browsed directory. `Ctrl+PageUp/PageDown` or `Cmd+Shift+[/]` switches sessions. Creating browsers claim control once on first frame; reattaching views reclaim only if they held confirmed control before an unexpected drop and no controller exists. Other viewers see read-only output with **Take control**.`Ctrl+F`/`Cmd+F`searches retained output;`Ctrl+Shift+C/V`(Win/Linux) or`Cmd+C/V\` (macOS) copies/pastes when controller; **Add selection to prompt** appends attributed text to the draft without submitting; **End session** confirms before terminating the shared PTY.

## Empty, Disabled, and Failure States

| Situation                          | User-facing behavior                                                                                                                            |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Computer sharing disabled          | Hide active Files/Changes/Terminal controls and explain the startup option in instance information                                              |
| Missing/invalid model or extension | Link the blocked conversation to its configuration diagnostic; preserve its prompt                                                              |
| API key rejected                   | Request a valid key while distinguishing access failure from lost project data; never repeat mutations after login                              |
| Browser offline                    | Mark presence/output as disconnected, preserve recoverable local work, disable execution submissions                                            |
| Draft synchronization failed       | Show unsynchronized state and retain recoverable text                                                                                           |
| File changed externally            | Preserve the local buffer and offer comparison/reload                                                                                           |
| Repository inspection failed       | Explain unavailable Git state explicitly                                                                                                        |
| Run failed                         | Show the owning operation error and retained evidence; keep deliberate recovery separate from retrying unknown effects                          |
| Server restarted                   | Restore unexpired composer drafts and continuation, disclose lost live authority, and never automatically resubmit input or recreate a terminal |

## Verifiable Flows

01. A person opens a configured Project, starts a conversation, and submits without entering the configuration center.
02. Two browsers coedit one prompt, observe one accepted submission, and retain any uncaptured edits.
03. One collaborator reads a file/diff while another stays in Chat; adding context is visible to both while navigation stays personal.
04. A busy Thread permits next-prompt editing without queueing or sending it automatically.
05. Applying Project defaults previews a bounded change and leaves an active Run's capture unchanged.
06. Native Files and Terminal remain on the server when the Agent uses E2B.
07. Terminal takeover changes input authority without disconnecting other viewers or replaying input.
08. Disabled sharing, missing Git, unsupported PTY, and authentication failures have distinct recovery paths.
09. Two people can see whether they are on the same Chat, file, or configuration page without synchronized navigation; multiple/background tabs stay distinguishable.
10. An Agent posts a final result to Inbox; the person sees the unread count, opens the item, lands on the posting card in the exact turn, and marks it Done without opening other chats.

## Debug Mode

Debug mode is a per-browser presentation preference, off by default, toggled from Diagnostics or `Cmd+Option+D` (`Ctrl+Alt+D` elsewhere) across owner and guest views. When enabled, surfaces reveal copyable identifiers, raw payloads, events, and token figures already held by the page without changing behavior or authority.

## Host Browser Drawer

The [Host Browser](../11-browser.md) shares the supporting panel with Files and Changes (resizable right panel in Side by side; full width in Tabs). It displays the remote browser desktop, defaults to read-only, and offers explicit **Take control** and **Hand back to Agent** actions; closing its tab detaches viewing without ending the Host browser or Agent Run.
