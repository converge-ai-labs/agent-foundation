# Agent Client Protocol

## Ownership

`a13n-harness-ui acp` serves [Agent Client Protocol (ACP)](https://agentclientprotocol.com/) v1 over stdio on POSIX systems. On Windows, the command reports that ACP is unavailable and exits nonzero before starting the App. Stdout carries only ACP frames; stderr carries diagnostics. The App owns admission, model execution, cancellation, and Thread state. An ACP session ID is the durable root Thread ID; connection admission, turn IDs, tool decisions, and ephemeral MCP entries are process-local. The ACP process runs under the selected Harness UI Environment. It is not a translation of a client's sandbox or network policy. Only trusted clients should be permitted to supply executable MCP commands, which run on the ACP host.

## Session and turn lifecycle

- `session/new` selects the Project by the existing exact-first-root rule. The `cwd` is an existing, absolute directory. `session/resume` accepts an existing, ordinary, unarchived and idle root Thread with no pending decision, and requires `cwd` to equal the canonical first saved local root. It does not change the Project, local roots, or saved composition and does not replay history. A pending resume and a prompt cannot overlap on the same session; an admitted prompt uses the MCP entries and overrides captured when it reserves its turn. Unknown sessions fail; `session/load` is not advertised.
- `session/prompt` accepts text and resource links, and serializes one turn per session. The server sends live assistant chunks, tool calls and status, observed plan changes, provider-supplied reasoning summaries from recognized providers, and usage reports. It never returns raw thinking or encrypted reasoning as ACP thoughts. When the client advertises `session.compaction` during `initialize`, the server forwards native compaction lifecycle transitions (`in_progress`, `completed`, `failed` with error details) and replacement summaries as `compaction_update` notifications keyed by `operation_id`, preserving terminal status regardless of whether the summary arrives before or after completion; clients that do not advertise `session.compaction` receive no compaction updates. Usage reports with known context size and occupancy use `usage_update`; other reports use `_a13n/usage_report`. A gap in detailed observation fails the response rather than claiming complete delivery. `session/cancel` prevents registration if it arrives before admission. Otherwise it requests cancellation of the active operation, including pending tool permissions; the prompt response waits for settlement. A prompt stopped by `session/cancel` returns `stopReason: cancelled`. JSON-RPC `$/cancel_request` cancels and joins any Run already admitted for that request before releasing the turn and returning the request-cancelled error.
- `session/set_config_option` accepts `model` and, when supported, `thought_level`. The options return the effective selection. Options can be changed between turns. These choices apply to operations on this connection, never update the Thread or configuration defaults, and are cleared on resume. A model change clears the reasoning-effort override.
- Interactive approvals use `session/request_permission`, keyed by the original tool call ID, with one-shot allow and reject options. The server never interprets an absent, cancelled or unrecognized choice as authorization. Latching turn cancellation or disconnect denies all approvals in a batch that has not been returned to the Run, including earlier allows. It also prevents new requests and late allows from taking effect. External input requests without a supported client mapping fail the tool call.

Input backpressure pauses reads without ending the ACP connection. Closing stdin ends the connection even if reads are paused. The process can discard queued stdout frames rather than waiting for the client to read them. App shutdown begins independently of ACP request cleanup and joins its Runs before closing storage. Transport shutdown does not guarantee a deadline for App cleanup that does not cooperate with cancellation.

## a13n profile version 1

The `initialize` result advertises `dev.a13n.harness-ui` under `_meta`, with `version: 1` and feature flags. A client may ignore the extension and use standard ACP. All extension data is JSON, and keys are case-sensitive.

| Message                                    | Profile fields and meaning                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `initialize` result                        | `version: 1` and `unattended`.                                                                                                                                                                                                                                                                                                                  |
| `session/prompt` request `_meta`           | Optional `turnId` (fresh for this session on the connection), and optional `inputIds` with one unique ID per content block. IDs are non-blank strings of 1–128 characters.                                                                                                                                                                      |
| `_a13n/input_accepted` notification        | `sessionId`, `turnId`, `inputId`. Emitted once per input on selected primary model-request evidence, before terminal.                                                                                                                                                                                                                           |
| `_a13n/steer` request                      | `sessionId`, `turnId`, `inputId`, `text`. Sends one input to that open turn, never starts a new turn and never forwards to a later turn.                                                                                                                                                                                                        |
| `_a13n/steer` result                       | `delivery`: `accepted`, `not_delivered`, or `unknown`. Accepted means the input was incorporated into the selected primary request boundary, not that a provider completed it. `not_delivered` means the input did not enter a primary request. Connection loss or an unresolved checkpoint outcome is unknown; do not replay an unknown input. |
| `_a13n/inventory`                          | Request `sessionId`. Returns `defaultModel`, `models`, `skills`, `mcpServers` (admitted server names and sources), and `omittedMcpServers` (request-local omissions and reasons). When a Run has prepared its tools, `omittedTools` reports names and reasons from the last prepared surface. Inventory does not start MCP servers.             |
| `session/update` `_meta`                   | Assistant chunks may carry `messageId`. `usage_update` carries `usageReport` with the Harness usage records.                                                                                                                                                                                                                                    |
| `_a13n/usage_report` notification          | `sessionId`, `version: 1`, and `usageReport`. Sent when context size or occupancy is unknown. Standard clients may ignore the extension.                                                                                                                                                                                                        |
| Successful `session/prompt` result `_meta` | `finalOutput`, `finalOutputOmitted`, and, when selected, `finalMessage` with the committed `continuationId` and transcript `position`. Only this result identifies the committed final answer; earlier chunks can be commentary or partial output.                                                                                              |

The primary request checkpoint and subsequent terminal checkpoints follow the [selected continuation rules](03-local-storage-and-recovery.md). The App omits steer input that has not reached the primary model-request evidence boundary from later continuation cuts, including the recovery input ledger. The same input ID is never reoffered within a turn. A stale, ended or not-yet-admitted turn fails closed. Clients must use a new `turnId` for every identified prompt in a session on the same connection. The server matches only the open turn and does not retain prior turn IDs. Missing notifications are not proof of non-delivery.

## MCP and unattended operation

Standard `mcpServers` accepts stdio entries for `session/new` and `session/resume`. They are used for this connection's session, started on demand for a Run, and not saved in the owner's configuration, Thread metadata, or composition recipe. Commands use the session directory as their working directory. Send them again on resume when needed.

With `--unattended`, an MCP entry is omitted unless the same request includes `_meta["dev.a13n.harness-ui"]` with `version: 1` and `unattendedSafeMcpServers`, an array naming entries declared safe by the client. Duplicate names and names not supplied in `mcpServers` are invalid parameters. For every omitted entry, the response carries `omittedMcpServers: [{"name": "…", "reason": "unattended_safety_not_declared"}]` in the same namespace, and stderr records the omission. Omitted entries do not launch. The declaration permits launching the supplied stdio command only. Tool calls still follow effective permissions, and elicitation remains unavailable.

Unattended operations do not suspend for a human. The effective Tool Surface hides external-input tools and tools with static approval or denied permission, including through Tool Search, CodeAct and children. Configured MCP servers do not require a trust declaration; their tools follow effective permissions. MCP elicitation and browser handback waits are unavailable. Argument-dependent approval and unexpected deferral fail the call without granting approval. A saved pending decision blocks admission. One-shot `run` uses this policy without an opt-out.

## Outbound ACP in local chats

WebUI runs configured external ACP executables on the local Full Control Host without Device bindings. The child inherits the Host environment except the two private MCP bridge variables; on POSIX, an existing `~/.local/bin` is appended when absent. The first local root is `cwd`; supported `additionalDirectories` contains only other project roots. System guidance uses standard `systemPrompt` append when advertised, or Antigravity's `_meta.antigravity.systemPrompt.append` when negotiated.

Session instructions always include `~/.a13n-harness-ui/AGENTS.md` global guidance when configured, plus preset-aware workspace `AGENTS.md` handling: presets that natively load workspace `AGENTS.md` (`antigravity`, `codex`, `opencode`, `github_copilot`, `goose`, `kimi_cli`) do not duplicate `<cwd>/AGENTS.md`; `claude_code` and `gemini_cli` inject `<cwd>/AGENTS.md` bounded to 32 KiB UTF-8 when present; `custom` presets receive a one-line path pointer when `<cwd>/AGENTS.md` exists; additional project roots with `AGENTS.md` are listed concisely by path. Session instructions also include an `<available-skills source="harness-ui">` index listing all discovered Skills (Project `.agents/skills`, Content Plugins, `~/.agents/skills`, and built-in Skills) with real Host absolute `SKILL.md` paths, and mention `harness-host` `ask_user_question` and `post_to_inbox` only when those tools are present in the prepared catalog.

Per-turn dynamic context tracks delivered `(source_id, key, sha256)` digests on the Thread's ACP session state so unchanged context blocks and `<inbox-reminder>` are not repeated on every turn. Delivered context resets on fresh sessions, completed `SessionUpdateCompactionUpdate`, Clear context, or session digest changes. The [Current Agent Context](02-agent-composition-and-snapshots.md#current-agent-context) reads the live peer model from standard `configOptions` or the legacy `models` fallback. A change in the projected `Current Model` refreshes the block on the next eligible prompt; after a reset, the block is sent again with the current value.

Native-only Environment mount JSON (`a13n.environment` / `a13n.environment-mounts`) and raw `a13n-harness-ui.input-surface` provenance lines are omitted from outgoing ACP prompt blocks while retaining `<surface-context>` once per surface. Prompt preamble blocks are joined with `\n\n` and adjacent text blocks maintain `\n\n` boundaries so peers concatenating text blocks never merge metadata or attachments into user text.

Retained Thread attachments use sanitized ASCII file extensions (`content{ext}`, defaulting to `content` for legacy records) and resolve to real Host paths without listing internal Thread storage as a project root. Small UTF-8 text attachments (up to 64 KiB) use `EmbeddedResourceContentBlock` when the peer advertises `promptCapabilities.embeddedContext`; other local file attachments pair readable path text with `ResourceContentBlock` (`file://` URI). Retained image and audio attachments use negotiated `ImageContentBlock` / `AudioContentBlock` when supported and otherwise fall back to their Host file path; unretained raw binary inputs without peer support still fail with `acp_input_unsupported`. The `harness-host` MCP bridge preserves `ToolReturn.content` blocks (including image and audio binary content) alongside serialized `return_value` text.

### Discovery, authentication, and options

`GET /api/acp-agents/presets` reports the supported local CLI commands and executable discovery. Opening a saved ACP Agent in Settings probes `initialize` and `session/new`, then closes the test session when supported. Successful session creation means ready; ACP `-32000` means sign-in is required. Advertised protocol login can present URL and form requests. On POSIX, Antigravity Google sign-in opens a browser link and accepts the callback URL or code in a private WebUI form. Harness UI passes the value directly to `agy acp --login`; it is not retained in the input record. Terminal login remains available. A chat that receives `acp_auth_required` links to the Agent's authentication settings.

`GET /api/acp-agents/{agent_id}/options` discovers the peer catalog for a new chat. The preview gives the peer a short window to publish a late model selector before closing the session. The Host caches a starting catalog that includes a model selector by resource and resolved working directory with a bounded TTL. Opening Agent & Model in a new chat retries an incomplete preview. Model and other option changes are confirmed in a short-lived session; explicit choices travel with Thread creation and are reapplied before the first prompt. The preview session does not become the Thread session.

An idle chat prepares its ACP session on the first options read. Discovery exposes the Host tool catalog; tool execution is authorized only while a real prompt owns the session. The initial prompt reuses the matching live resident session. When an initial prompt opens a fresh Antigravity session, the Host gives a late model selector the same short discovery window before projecting prompt context. Opening Agent & Model in an idle chat refreshes the resident options, including any received `config_option_update`.

WebUI shows the peer's effective model, thinking level, and mode when offered. Standard `configOptions` take precedence; peers with only legacy `models` use `session/set_model`. A select option with a missing or null current value remains selectable and appears unselected. The peer's option response replaces the current choice list, including thinking levels that change with the model. Changing the peer's model clears cached context-window occupancy unless the peer emits a fresh `usage_update` during the change.

The Thread stores the matching session identity and effective option values separately from its continuation. Discovery preserves saved choices for options missing from the current snapshot. When a resident connection is lost before the first prompt, or the peer explicitly rejects that first prompt before any turn activity, recovery opens a new session with `session/new`. A completed prompt, observed turn activity, or an interrupted prompt with an unknown outcome keeps the session eligible for `session/resume` or `session/load` to preserve peer history. Both paths reapply supported saved options with the model first. Clear context retires the resident and clears its recoverable identity.

### Active prompts and transcript

Peers can negotiate `_meta.steering.supported` at initialization. `_session/steering` sends the active `sessionId` and multimodal `prompt` blocks (sharing the turn prompt-block builder for images, attachments, and Skill selections); `injected` confirms delivery and `promptRequired` does not. Text-only `_a13n/steer` gracefully converts retained file attachments to readable Host paths and rejects unretained unsupported binaries. An accepted native steer is recorded in the active transcript. An unknown outcome is not replayed.

When native steering is unavailable or definitely did not deliver the input, the Host queues ordinary prompt blocks on the same Run and session. Immediate steering requests `session/cancel`; queued steering and prompt-guest fallback wait for natural settlement. The Host waits for the active prompt to settle before sending the next `session/prompt` on that session. A peer that fails to settle after an interrupt fails the Run without a new prompt or a reconnect. Queue acceptance does not confirm peer delivery. Explicit Stop ends the Run and discards undispatched steering. An empty composer offers **Stop**.

Live and retained tool rows carry ACP title, kind, status, locations, and content. File locations open through the existing Host file viewer when available. Structured and successfully applied Antigravity edits use the standard diff viewer. Qualified `harness-host` MCP calls project as ordinary Host tools. The current plan is updated in place. Outbound sessions advertise `session.compaction`; peer `compaction_update` and `compaction_summary_chunk` notifications aggregate by `compactionId` into in-place compaction activity cards (preserving status, bounded summary text, and failure diagnostics across live and saved transcripts) without affecting final replies or prior-conversation handoff. Only a completed compaction triggers Goal restore audit and invalidates stale context-window occupancy until a newer `usage_update` arrives. Context-window occupancy uses the connected live resident as authority (including explicit clears after compaction or model switches, and prewarmed sessions with reported usage) before falling back to saved session state, persists observed occupancy changes even if a turn fails or is cancelled, appears in Composer (and TUI status) when available, and hides the Composer Context metric outside Debug mode when the external peer has not reported occupancy. A streamed Thought closes at the next answer or tool call, or when the turn settles; its elapsed time and received text remain available in the work log. Prompt response usage contributes to the Thread token ledger, with cached tokens counted within input and thinking tokens within output. A peer can name an untitled Thread or replace its last applied title; a different user title takes precedence, and Clear context and Fork preserve the existing Thread title against subsequent peer auto-titles. Peer-advertised commands and Harness UI Skills are both available in the Composer (`$` for Skills, leading `/` merging peer commands and Skills with clear source labels), and peer commands are restored from saved session data. Typing a leading `/<skill-name>` directly without autocomplete attaches the matching Harness UI Skill reference whenever `<skill-name>` is not a peer command.

Changing to an ACP Agent clears the native default Model and ignores native per-turn controls. Returning to a matching ACP session resumes its own history; the next prompt carries bounded, visible conversation history the session has not seen. Native Agents receive ACP user messages and text replies through the regular Thread continuation. Forking or branching an ACP Thread retains the selected transcript and ACP option choices without sharing the source session; the next ACP prompt opens a new session and carries visible prior history through the same bounded prefix. Promoting an ordinary ACP Thread to Coordinator likewise retires its existing session and preserves saved ACP option choices and commands so the next prompt or options read opens a Coordinator session with updated Host tools (`create_worker`), Coordinator guidance, Coordinator built-in Skills, and bounded visible prior history; idempotent re-promotion leaves an active Coordinator session intact. [Editing a sent input](04-projects-threads-and-environments.md#edit-a-sent-message) retires the current session and resets the saved session ID, prompt status and context window. The ACP digest, commands and option selections remain available. The next prompt opens a fresh session with the cropped visible prior history.
