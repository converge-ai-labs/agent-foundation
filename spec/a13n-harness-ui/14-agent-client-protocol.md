# Agent Client Protocol

## Ownership

`a13n-harness-ui acp` serves [Agent Client Protocol (ACP)](https://agentclientprotocol.com/) v1 over stdio on POSIX systems. On Windows, the command reports that ACP is unavailable and exits nonzero before starting the App. Stdout carries only ACP frames; stderr carries diagnostics. The App owns admission, model execution, cancellation, and Thread state. An ACP session ID is the durable root Thread ID; connection admission, turn IDs, tool decisions, and ephemeral MCP entries are process-local. The ACP process runs under the selected Harness UI Environment. It is not a translation of a client's sandbox or network policy. Only trusted clients should be permitted to supply executable MCP commands, which run on the ACP host.

## Session and turn lifecycle

- `session/new` selects the Project by the existing exact-first-root rule. The `cwd` is an existing, absolute directory. `session/resume` accepts an existing, ordinary, unarchived and idle root Thread with no pending decision, and requires `cwd` to equal the canonical first saved local root. It does not change the Project, local roots, or saved composition and does not replay history. A pending resume and a prompt cannot overlap on the same session; an admitted prompt uses the MCP entries and overrides captured when it reserves its turn. Unknown sessions fail; `session/load` is not advertised.
- `session/prompt` accepts text and resource links, and serializes one turn per session. The server sends live assistant chunks, tool calls and status, observed plan changes, provider-supplied reasoning summaries from recognized providers, and usage reports. It never returns raw thinking or encrypted reasoning as ACP thoughts. Usage reports with known context size and occupancy use `usage_update`; other reports use `_a13n/usage_report`. A gap in detailed observation fails the response rather than claiming complete delivery. `session/cancel` prevents registration if it arrives before admission. Otherwise it requests cancellation of the active operation, including pending tool permissions; the prompt response waits for settlement. A prompt stopped by `session/cancel` returns `stopReason: cancelled`. JSON-RPC `$/cancel_request` cancels and joins any Run already admitted for that request before releasing the turn and returning the request-cancelled error.
- `session/set_config_option` accepts `model` and, when supported, `thought_level`. The options return the effective selection. Options can be changed between turns. These choices apply to operations on this connection, never update the Thread or configuration defaults, and are cleared on resume. A model change clears the reasoning-effort override.
- Interactive approvals use `session/request_permission`, keyed by the original tool call ID, with one-shot allow and reject options. The server never interprets an absent, cancelled or unrecognized choice as authorization. External input requests without a supported client mapping fail the tool call.

Input backpressure pauses reads without ending the ACP connection. Closing stdin ends the connection even if reads are paused. The process can discard queued stdout frames rather than waiting for the client to read them. App shutdown begins independently of ACP request cleanup and joins its Runs before closing storage. Transport shutdown does not guarantee a deadline for App cleanup that does not cooperate with cancellation.

## a13n profile version 1

The `initialize` result advertises `dev.a13n.harness-ui` under `_meta`, with `version: 1` and feature flags. A client may ignore the extension and use standard ACP. All extension data is JSON, and keys are case-sensitive.

| Message                                    | Profile fields and meaning                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `initialize` result                        | `version: 1` and `unattended`.                                                                                                                                                                                                                                                                                                                  |
| `session/prompt` request `_meta`           | Optional `turnId` (fresh for this session on the connection), and optional `inputIds` with one unique ID per content block. IDs are non-blank strings of 1–128 characters.                                                                                                                                                                      |
| `_a13n/input_accepted` notification        | `sessionId`, `turnId`, `inputId`. Emitted once per input on selected primary model-request evidence, before terminal.                                                                                                                                                                                                                           |
| `_a13n/steer` request                      | `sessionId`, `turnId`, `inputId`, `text`. Sends one input to that open turn, never starts a new turn and never forwards to a later turn.                                                                                                                                                                                                        |
| `_a13n/steer` result                       | `delivery`: `accepted`, `not_delivered`, or `unknown`. Accepted means the input was incorporated into the selected primary request boundary, not that a provider completed it. `not_delivered` means the input did not enter a primary request. Connection loss or an unresolved checkpoint outcome is unknown; do not replay an unknown input. |
| `_a13n/inventory`                          | Request `sessionId`. Returns `defaultModel`, `models`, `skills`, `mcpServers` (admitted server names and sources), and `omittedMcpServers` (request-local omissions and reasons). When a Run has prepared its tools, `omittedTools` reports names and reasons from the last prepared surface. Inventory does not start MCP servers.             |
| `session/update` `_meta`                   | Assistant chunks may carry `messageId`. `usage_update` carries `usageReport` with the Harness usage records.                                                                                                                                                                                                                                    |
| `_a13n/usage_report` notification          | `sessionId`, `version: 1`, and `usageReport`. Sent when context size or occupancy is unknown. Standard clients may ignore the extension.                                                                                                                                                                                                        |
| Successful `session/prompt` result `_meta` | `finalOutput`, `finalOutputOmitted`, and, when selected, `finalMessage` with the committed `continuationId` and transcript `position`. Only this result identifies the committed final answer; earlier chunks can be commentary or partial output.                                                                                              |

The primary request checkpoint and subsequent terminal checkpoints follow the [selected continuation rules](03-local-storage-and-recovery.md). The App omits steer input that has not reached the primary model-request evidence boundary from later continuation cuts, including the recovery input ledger. The same input ID is never reoffered within a turn. A stale, ended or not-yet-admitted turn fails closed. Missing notifications are not proof of non-delivery.

## MCP and unattended operation

Standard `mcpServers` accepts stdio entries for `session/new` and `session/resume`. They are used for this connection's session, started on demand for a Run, and not saved in the owner's configuration, Thread metadata, or composition recipe. Commands use the session directory as their working directory. Send them again on resume when needed.

With `--unattended`, an MCP entry is omitted unless the same request includes `_meta["dev.a13n.harness-ui"]` with `version: 1` and `unattendedSafeMcpServers`, an array naming entries declared safe by the client. Duplicate names and names not supplied in `mcpServers` are invalid parameters. For every omitted entry, the response carries `omittedMcpServers: [{"name": "…", "reason": "unattended_safety_not_declared"}]` in the same namespace, and stderr records the omission. Omitted entries do not launch. A declaration does not bypass an explicit tool deny or ask or enable elicitation.

Unattended operations do not suspend for a human. The effective Tool Surface hides external-input tools and tools with static approval or denied permission, including through Tool Search, CodeAct and children. Configured MCP servers do not require a trust declaration; their tools follow effective permissions. MCP elicitation and browser handback waits are unavailable. Argument-dependent approval and unexpected deferral fail the call without granting approval. A saved pending decision blocks admission. One-shot `run` uses this policy without an opt-out.
