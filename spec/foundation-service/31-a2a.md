# A2A Discovery and Runtime

## Design Position

Foundation Service implements [A2A 1.0](https://a2a-protocol.org/v1.0.0/specification/) over the standard HTTP+JSON binding for every callable AgentPreset when the deployment-wide `a2a_enabled` setting is true. A2A is a protocol adapter over Foundation application authority: an A2A Context binds an authorized Foundation Session and root Thread, while an A2A Task is a durable protocol projection over one or more Runs advancing that Thread. Neither is a second execution or scheduling authority.

The Foundation A2A profile implements discovery, required Task operations, streaming, authenticated extended Agent Cards, and push notifications. It does not implement parallel JSON-RPC or gRPC bindings and declares no Foundation protocol extension.

## Version and Binding

Every A2A runtime request selects:

- `A2A-Version: 1.0`;
- `Content-Type: application/a2a+json` where a body is present; and
- the Agent Card interface with `protocolBinding="HTTP+JSON"` and `protocolVersion="1.0"`.

Missing or incompatible version selection fails with the A2A binding's version error. JSON fields use the A2A camelCase wire names. Foundation does not reinterpret `/api/v1` JSON conventions as A2A conventions.

The Agent Card advertises no A2A extensions. A non-empty `A2A-Extensions` request that is not declared by the selected Card fails through the standard extension-support error. Unknown extension content never enters Agent input, metadata, Harness state, or a model prompt.

Foundation omits `tenant` from every `AgentInterface`. A request cannot encode a Foundation Organization or Workspace as an A2A tenant; non-empty tenant selection is rejected.

## Addressing and Discovery

Each callable AgentPreset has a direct base URL:

```text
https://<authority>/a2a/v1/agent-presets/{agent_preset_id}
```

Its direct public Agent Card URL is:

```text
https://<authority>/a2a/v1/agent-presets/{agent_preset_id}/agent-card.json
```

All standard operation paths below are relative to the direct base URL. Every accepted hostname can map at most one deployment-selected default AgentPreset to:

```text
GET /.well-known/agent-card.json
```

The root well-known route is a static hostname mapping. It never chooses an AgentPreset from an Authorization header, Workspace header, query parameter, current user, or other request state. A hostname with no default mapping returns not found. Additional AgentPresets use their direct Card URL, an external catalog, or another hostname.

### Agent Card Projection

The public Card is a deterministic safe projection of the AgentPreset's current active AgentPresetVersion, its ProtocolConfig, and deployment-owned authority mapping. It accurately declares:

- the preferred HTTP+JSON interface and protocol version;
- public name, description, skills, Foundation-supported input modes, and configured output modes;
- `streaming=true` and `pushNotifications=true`;
- `extendedAgentCard=true` only when an extended projection is configured;
- real security schemes required by runtime operations; and
- no unsupported binding, operation, extension, or capability.

The public projection contains no Workspace ID, internal Version identity, Secret, credential, private endpoint, tool implementation, hidden capability, provider state, object key, or internal execution identity. It is independent of the requesting Principal, returns a strong `ETag`, and uses bounded public cache policy.

When declared, the standard `GET /extendedAgentCard` operation authenticates the caller, authorizes the AgentPreset-scoped read, and returns a separately generated extended projection with `Cache-Control: private, no-store`. Authentication alone does not grant every private capability.

Foundation-generated public and extended Cards omit JWS signatures. Production serves them only through the authoritative HTTPS origin. Wire models remain compatible with the standard `signatures` field, but Foundation neither signs Cards nor establishes signature trust. TLS, runtime authentication, and authorization remain required.

## Operation Surface

| Operation               | HTTP+JSON path                                          | Foundation behavior                                                               |
| ----------------------- | ------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Send Message            | `POST /message:send`                                    | Accept or continue a Task and return a Task response                              |
| Send Streaming Message  | `POST /message:stream`                                  | Accept or continue a Task and stream `StreamResponse` over SSE                    |
| Get Task                | `GET /tasks/{id}`                                       | Return current authorized Task projection                                         |
| List Tasks              | `GET /tasks`                                            | Return bounded authorized Tasks for this AgentPreset and caller                   |
| Cancel Task             | `POST /tasks/{id}:cancel`                               | Invoke durable interrupt for the current associated Run; its outcome is cancelled |
| Subscribe to Task       | `POST /tasks/{id}:subscribe`                            | Stream a non-terminal Task's current snapshot and later updates                   |
| Create push config      | `POST /tasks/{id}/pushNotificationConfigs`              | Create an authorized future-delivery configuration                                |
| Get push config         | `GET /tasks/{id}/pushNotificationConfigs/{configId}`    | Read safe configuration metadata                                                  |
| List push configs       | `GET /tasks/{id}/pushNotificationConfigs`               | Page through authorized configurations                                            |
| Delete push config      | `DELETE /tasks/{id}/pushNotificationConfigs/{configId}` | Fence and remove one configuration                                                |
| Get extended Agent Card | `GET /extendedAgentCard`                                | Return the authorized private Card projection                                     |

Send Message always selects the Task branch of the standard response union; it never returns a direct response Message. `returnImmediately=true` returns after durable Task and Run acceptance. When false or absent, the attachment waits for the Task to reach a terminal or interrupted state under the bounded request deadline. Attachment timeout or disconnect leaves the Task running, and the client reconciles with Get Task or Subscribe to Task.

## Authentication and Identity

Public Agent Cards require no credential. Every non-public runtime, Task, extended-Card, and push-configuration operation maps the Card-declared credential to an existing Foundation User or Service Account `PrincipalRef`. The OSS profile uses its existing browser session or Workspace-bound bearer API key contracts and defines no A2A Principal, role, API-key type, or credential store.

Extended Agent Card reads authorize `agent_preset.read`; Task Get, List,
Subscribe, and resubscribe authorize `run.read`; new Message work authorizes
`agent_preset.invoke` and the applicable `run.continue` or `run.feedback`
action; Task cancellation authorizes `run.interrupt`; and push-configuration
List/Get and mutations authorize `a2a_push_configuration.read` and
`a2a_push_configuration.manage`. These actions and built-in grants come from
the IAM
[stable action registry](10-identity-and-access-management.md#stable-action-registry).
The public Agent Card is the only anonymous action exception.

Every operation reauthorizes the current AgentPreset, Task/Context binding, content, and requested action. A2A IDs, Message IDs, Task IDs, Context IDs, Artifact IDs, configuration IDs, URLs, tokens, and metadata grant no authority.

## Context and Task Bindings

The adapter persists explicit bindings with this conceptual meaning:

```python
class A2AContextBinding:
    context_id: str
    client_identity: str
    agent_preset_id: str
    session_id: SessionId
    root_thread_id: ThreadId


class A2ATaskBinding:
    task_id: str
    context_id: str
    agent_preset_id: str
    agent_preset_version_id: str
    thread_id: ThreadId
    ordered_run_ids: tuple[RunId, ...]
    client_tool_surface_digest: str
```

The records also retain stable Message/Artifact bindings, exact Asset references when applicable, and idempotency evidence. They do not contain credentials, RunAttempt identity, Worker lease, Redis cursor, Harness Run identity, object-storage keys, or provider state.

One Context advances one Session root Thread serially. At most one Task in that Context is non-terminal. The accepted forms are:

| Incoming Message reference | Accepted operation                                                                                                                                                              |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| no Context or Task         | Create a Context, Session, root Thread, Task, and first Run                                                                                                                     |
| existing Context, no Task  | After its prior Task is terminal, create another Task and continuation Run                                                                                                      |
| existing Task              | Only while `TASK_STATE_INPUT_REQUIRED` or `TASK_STATE_AUTH_REQUIRED`, accept explicit feedback or an ordinary Message that defaults the pending set and continues the same Task |

New-Task and continuation acceptance call the common [Agent control contract](34-agent-control-input-and-continuation.md). Same-Task feedback uses its correlated complete-batch deferred-interaction boundary, including default reject and no-response outcomes for omitted calls. An ordinary Agent-input Message sent while the Task is input/auth required has the A2A-profile meaning “abandon the outstanding interaction and handle this message”: the adapter reads the exact waiting digest, sets `waiting_resolution.mode="defaults"`, and accepts one `waiting_continue` Run whose first model request receives both default deferred results and the mapped `AgentInput`. Existing queued submissions remain untouched. Task cancellation calls the durable [active-execution command](35-agent-control-active-execution.md). The A2A adapter defines no parallel Run mutation path.

A Message cannot steer a `TASK_STATE_SUBMITTED` or `TASK_STATE_WORKING` Task, implicitly queue behind it, reopen a terminal Task, or change the Task's AgentPreset, AgentPresetVersion, protocol configuration, or client tool surface. Same-Task feedback and waiting Continue reuse the values frozen at first acceptance. Explicit feedback content and ordinary abandonment input are mutually exclusive in one Message. A stale waiting digest or concurrent advancement fails without partial Task/Run advancement or inbox rebinding. A later Task in the Context can select the AgentPreset's current active Version only when Foundation continuation compatibility accepts the existing Thread state; otherwise the client starts a new Context.

## Task State Projection

A2A Task state is derived from durable Foundation facts:

| Foundation fact                                            | A2A state                   |
| ---------------------------------------------------------- | --------------------------- |
| accepted or queued current Run                             | `TASK_STATE_SUBMITTED`      |
| running current Run                                        | `TASK_STATE_WORKING`        |
| sealed waiting for user, approval, or client-tool feedback | `TASK_STATE_INPUT_REQUIRED` |
| sealed recoverable authentication challenge                | `TASK_STATE_AUTH_REQUIRED`  |
| sealed successful outcome                                  | `TASK_STATE_COMPLETED`      |
| sealed failure                                             | `TASK_STATE_FAILED`         |
| sealed cancellation                                        | `TASK_STATE_CANCELED`       |

Authentication, validation, policy, version, or staging failure before Task acceptance is an A2A protocol error and creates no `TASK_STATE_REJECTED` Task. Foundation uses `TASK_STATE_REJECTED` only when an owning durable fact explicitly records an accepted Task rejection; it never manufactures that state from an HTTP failure.

A Task can contain several ordered Runs when feedback or explicit default abandonment continues the same A2A operation. Task state, output, history, and cancellation use the current associated Run and committed Task bindings rather than the latest timestamp or a temporary stream observation. Waiting-bound steer and async results remain invisible to the composite successor's first model request and enter only when the Foundation-owned awaited delivery hook reaches its later safe boundary.

## Messages, Parts, and Artifacts

Messages carry accepted client input, feedback, authentication challenge, or meaningful interaction status. Task results, including ordinary assistant text, use Artifacts. Task history retains accepted client Messages and the bounded Agent Messages needed to recover `TASK_STATE_INPUT_REQUIRED` or `TASK_STATE_AUTH_REQUIRED`; it does not copy token deltas, ordinary progress, reasoning, logs, or complete Harness history.

An accepted A2A client Message maps to one canonical [`AgentInput`](33-agent-input.md). Text Parts preserve order as text content, data Parts map to `structured_content`, and raw or URL Parts are imported into immutable Workspace [Assets](37-asset-management.md) before their exact IDs enter binary input. The common Agent input contract and selected AgentPresetVersion's frozen ProtocolConfig remain authoritative; A2A metadata, Task IDs, Context IDs, and protocol options never enter Agent input implicitly.

Each Part contains exactly one of `text`, `data`, `raw`, or `url`:

- `text` is bounded UTF-8;
- `data` is bounded JSON validated by the selected Version's `input_data_schema` when present;
- `raw` is decoded, size/MIME/digest checked, scanned by content policy, and staged as one candidate Asset before Run acceptance; and
- `url` is fetched by a bounded importer with scheme, redirect, DNS/IP, port, timeout, size, MIME, and credential-forwarding controls, then staged as one candidate Asset before acceptance.

An arbitrary URL is never handed to Harness or the model. Raw and URL import requires current `asset.create` and `asset.use` authority in addition to the A2A Send action. Candidate object publication occurs outside the database transaction. The final short acceptance transaction creates each immutable Asset, binds the A2A Message, and accepts the Task/Run together; the resulting `AgentInput` stores only exact `asset_id` values. If final acceptance fails, no Asset, Task, or Run row commits and the candidate objects are cleanup candidates. Message-idempotency replay returns the original Asset and Run bindings rather than publishing the same Part again. Failed feedback staging leaves the interrupted Task unchanged.

The imported Asset uses the Part's validated filename when present or the deterministic display name `part-{part_index}` when absent. Its media type uses the normalized Part value or `application/octet-stream`. Neither value changes the Asset object key or grants authority.

Each Artifact has one stable Task-scoped `artifactId` and can bind one or more authorized Items, Run outputs, or exact Assets. A file/media Artifact produced from an Asset binds its immutable `asset_id`, reauthorizes content on every Task read or delivery, and projects standard raw or URL Parts according to the bounded A2A response policy. `artifactId` is not an `asset_id`, Foundation Item, object key, or content credential. Default projection produces one primary text response Artifact, data Artifacts for structured results, and distinct file/media Artifacts. Tools, approvals, plans, private reasoning, Worker events, and logs do not become Artifacts.

## Streaming and Subscription

Send Streaming Message and Subscribe to Task use standard A2A SSE `StreamResponse` values. For a non-terminal Task, the first response is its complete current Task snapshot. Later responses are ordered `TaskStatusUpdateEvent` and `TaskArtifactUpdateEvent` values for that Task.

An Artifact's first update uses its stable ID with `append=false`; later chunks use the same ID and `append=true`; its final chunk sets `lastChunk=true`. Foundation coalesces fine-grained model deltas into bounded chunks. The final Get Task projection equals the completely delivered Artifact content.

A terminal or interrupted status update is the last stream event and closes the attachment. Standard Subscribe to Task applies only to a non-terminal Task; a terminal Task returns the standard operation error and clients use Get Task for its final snapshot. After interrupted feedback accepts another Run in the same Task, the client can subscribe again.

A2A exposes no Native cursor. Reattachment starts from current Task state and new updates; ordinary progress has no reliable replay promise. Stable current status and final Artifacts remain recoverable through Get Task. Disconnect never cancels the Task.

## Push Notifications

One Task can own several bounded push configurations. Each configuration binds its server-generated ID, Task, creator Principal and client identity, normalized HTTPS destination, optional opaque client `token`, optional caller `authentication` scheme and credentials, state, protocol version, delivery generation, and bounded retry policy.

`token` lets the receiving client correlate or validate a configuration; `authentication.credentials` authenticates Foundation to the webhook. They are different write-only values protected by the [Secret boundary](11-secret-management.md). Get and List return safe URL, scheme, state, and metadata but never plaintext token or credentials. Logs, errors, audit, telemetry, and dead-letter diagnostics also omit them.

Production destinations are absolute HTTPS URLs without userinfo or fragment. Creation and every dispatch or redirect re-resolve and enforce destination policy, blocking loopback, private, link-local, metadata, multicast, unspecified, disallowed ports, DNS rebinding, credential forwarding, and unapproved redirects. Dispatch uses a separate bounded egress client or proxy with fixed connect/read deadlines, response limit, and redirect count.

Push delivers only committed significant Task facts: actionable interrupted status, terminal status, policy-selected significant submitted/working changes, and complete selected Artifacts. It sends no token delta, reasoning, log, or partial Artifact. The request body is the same standard `StreamResponse` shape used by A2A streaming, not a Foundation envelope.

Configuration creation receives future facts only and does not replay older Task events. The client uses Get Task after creation and after any delivery to reconcile complete state.

Delivery reuses the [durable outbox](06-durable-operations-and-outbox.md):

- each `(configuration, source fact)` has one stable delivery identity;
- delivery is per-configuration ordered and at least once;
- retries use finite bounded backoff before dead letter;
- authorized redrive preserves the same source and delivery identity; and
- duplicate, failure, acknowledgement, or dead letter never changes Task state.

Deleting a configuration disables it, increments its generation, prevents new claims, and drains or cancels the prior generation's dispatch before success. A request already sent across the network cannot be recalled, so deletion does not claim that the receiver did not observe it. Terminal Task commit records final selected Artifact/status intents with the terminal fact; their later delivery lifecycle is independent.

## Failure and Compatibility

| Failure                                                  | A2A outcome                                  | Foundation consequence                 |
| -------------------------------------------------------- | -------------------------------------------- | -------------------------------------- |
| Version, extension, body, or content negotiation invalid | Standard A2A error                           | No acceptance                          |
| AgentPreset, Context, Task, or content unauthorized      | Safe A2A denial/concealment                  | No unauthorized disclosure or mutation |
| Message ID repeats with same canonical content           | Original Task or result                      | No duplicate Run                       |
| Message ID repeats with different content                | Conflict error                               | Original binding unchanged             |
| Stream disconnects                                       | Client uses Get Task or Subscribe            | Task continues                         |
| Push delivery exhausts retries                           | Configuration delivery dead-letters          | Task unchanged                         |
| Cancellation races completion                            | Projection reports the owning durable winner | No state rewrite                       |

The exact A2A 1.0 data model, HTTP+JSON operation paths, service-parameter headers, errors, and media type form the upstream compatibility line. Foundation adds only safe projection and binding rules that do not change standard field meaning. A future A2A version or binding requires an explicitly compatible interface and cannot silently reinterpret retained Tasks.

## Invariants

01. Foundation implements A2A 1.0 HTTP+JSON and no parallel A2A binding.
02. One Context advances one authorized Foundation Session/root Thread serially.
03. A Task is a protocol projection over one or more Runs, never execution authority.
04. A working or terminal Task cannot be steered, queued behind, or reopened.
05. Results use Artifacts; Messages do not become an alternate result channel.
06. Standard streaming has no Native cursor, and disconnect never cancels a Task.
07. Push delivery is at least once and cannot change Task outcome.
08. Agent Cards expose only safe accurate capability projections and omit JWS signatures.
09. A2A identifiers, URLs, tokens, and metadata grant no Foundation authority.
10. An ordinary Message against an input-required Task explicitly defaults the complete waiting set and continues it in one Run; explicit feedback remains a distinct mutually exclusive mapping.
