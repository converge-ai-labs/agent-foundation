# Environment monitoring

## Design position

Monitoring associates a workspace's live Metrics Data Sources with Environment instances. Collection, external delivery and historical querying have independent completion and failure boundaries. Environment lifecycle operations and Runs retain their existing ownership; monitoring never starts an execution Session, resumes a stopped target or recreates an instance.

[Environment lifecycle](06-environments.md) owns instances and provider handles. This chapter owns monitoring configuration, source selection, observation and query authority. [Service observability](12-observability.md) owns telemetry about the Service itself.

## Data sources

A Metrics Data Source (`mds_`) is a live workspace resource with the normal version, strong ETag and audit conventions. Its public configuration contains a collection mode, optional OTLP export, optional Prometheus HTTP query configuration, and the optional deployment collector selected for pull. Export and query endpoints and credentials are independent.

| Collection | Required configuration | Behavior                                                                                                |
| ---------- | ---------------------- | ------------------------------------------------------------------------------------------------------- |
| `native`   | OTLP export            | A supported managed Envd launch receives metrics-specific exporter settings.                            |
| `pull`     | Deployment collector   | The configured collector scrapes eligible HTTP targets and uses its operator-owned delivery pipeline.   |
| `proxy`    | None                   | Service reads cached EIP observations and retains bounded temporary history, optionally exporting OTLP. |
| `external` | Prometheus query       | Operators own ingestion; Service only queries history.                                                  |

The built-in **Local Cache** is a selectable, enabled proxy source without external export or query. It is materialized once per workspace on first discovery. Its fixed configuration cannot be changed or deleted. Custom sources have independent names and enabled states. An Environment's `metrics_data_source_id` defaults to NULL: no automatic collection or exporter injection and no implicit selection of Local Cache.

Data-source administration requires workspace `admin`, including connectivity tests. Members with `read` can list secret-free source metadata and configuration for selection. Source updates use `If-Match`; no-op updates keep their version. Credentials are encrypted separately for the exact organization, source row and export/query column. They are write-only, represented by presence flags. An omitted credential retains its current value; explicit null clears it; an object replaces it. Changing a destination requires explicitly replacing or clearing that destination's credential. Removing a capability clears its credential.

Endpoints contain no userinfo, query parameters or fragments. Header values belong in the encrypted credential, never the public configuration. Configuration and every outbound request follow the deployment endpoint policy. Disabling a source stops subsequent managed collection and queries; it does not revoke credentials already delivered to a target. Deletion is refused while Environment references remain, including under concurrent binding changes.

## Deployment preset

A deployment can offer one pull-collection preset: a suggested name, collector and Prometheus query API base. An explicit workspace ID allowlist controls both discovery and use; an empty allowlist exposes it to nobody. Discovery requires workspace administration and returns only public configuration, a public-configuration revision and a query-credential presence flag. A configured query bearer token remains in Service. Operators must scope that token at the backend to the data every allowlisted workspace administrator may query; scope labels do not enforce this boundary.

Console pre-fills new-source forms from this preset. Saving explicitly creates an ordinary source in the current workspace; deployment startup never creates sources or selects them for Environments. The create request identifies the displayed preset revision and explicitly opts into its query credential. Service rechecks workspace administration, allowlist eligibility and the current revision. Credential inheritance additionally requires the original query endpoint and cannot be combined with supplied query credentials. Editing the endpoint requires clearing the opt-in or supplying a different credential. Preset revisions cover public configuration and credential presence, not secret values.

Confirmation snapshots the current deployment credential into the source's existing encrypted storage. Later deployment changes, removal, allowlist changes and token rotation do not mutate saved sources. Administrators rotate existing source credentials explicitly, or create and bind a newly confirmed source. Updating a saved source retains the normal credential and ETag rules.

## Selection and authority

An Environment selects at most one same-workspace source. Selection before a supported managed create supplies the launch configuration; later selection and the configuration actually applied to a target remain distinct. Source changes do not migrate or join histories. External targets require manual native configuration. Starting an existing container does not update its environment variables.

Bindings retain Environment management authority and conditional updates. An external endpoint's self-reported Device identity requires administrator approval before association with any custom source, including a source that gains query capability later. Selecting the immutable Local Cache and clearing a binding retain ordinary Environment management authority. Adding, changing or clearing custom exact-match mapping labels on a selected source requires administration authority; retaining the same binding and labels does not. Removing the binding also removes its labels and retains ordinary management authority. Source scope labels cannot be overridden. A deleted Environment retains its historical binding, which its manager can explicitly clear with `If-Match` to release the source reference; it cannot select another source. Typed Environment queries authorize the Environment, including its private-owner boundary, before resolving its source or contacting a backend. Historical data does not establish current Device reachability.

Arbitrary PromQL and preview require a separate data-source query authorization: workspace `admin`. Environment read permission alone never grants access to arbitrary queries using shared credentials. Query credentials must be backend-scoped to the workspace's permitted data. Scope labels are filters for built-in queries, not tenant authorization or a restriction on arbitrary PromQL. Query credentials remain in Service; native targets receive only appropriately scoped write credentials, outside the ordinary frozen recipe and public handle.

Publishing a native source makes its write credential usable by managers of supported managed Environments. Native injection delivers that credential to the target process; users and agents with execution authority there can read and reuse it. Administrators must provision write-only credentials scoped by the receiver to the intended ingestion boundary and trust those target executors within that boundary. Service resource labels are correlation metadata, not proof of sample identity, and do not prevent a credential holder from submitting other labels. Deployments that cannot grant this trust use pull or proxy collection, keeping receiver credentials outside the target. Requiring an administrator to select a source alone would not hide an injected credential from a target's other executors.

Monitoring management and query routes are human-facing and are excluded from Agent tools and MCP admission.

## Managed launch and applied state

Managed Docker and E2B recipes using `envd_http` enable Envd's 10-second sampler at creation for selected native, proxy and pull sources. Native selection additionally supplies exporter settings; proxy and pull supply no exporter credentials or OTEL settings. External collection and no selection inject no monitoring settings. Other recipes remain usable with proxy/pull selections but receive no sampler injection and remain unsupported for collection unless their provider exposes it. Unsupported recipes refuse native export before dispatch.

The first lifecycle claim freezes the selected source version, collection mode, sampler interval and optional export settings in an encrypted Environment-local launch snapshot, independently of the ordinary handle. A later binding or source edit does not change that creation input, including after a lost response or expired claim. Existing targets require operator configuration when their daemon has no sampler; neither a poll nor a start/resume injects late settings.

Native creation receives metrics-specific OTEL settings with write headers and stable Environment, workspace and organization resource attributes. Query credentials stay in Service. The snapshot, headers and exporter settings are excluded from recipes, target fingerprints, portable provider state and public representations. The deployment's sandbox runtime must include Envd's native OTLP capability. Native HTTP endpoints are complete metrics URLs; gRPC endpoints name the collector origin.

`metrics_application` is the secret-free launch receipt: `source_id`, `source_version`, `collection`, `sample_interval_ms` and nullable `applied_at`. Before a successful fenced create publication, `applied_at` is null. Successful creation records the application time and erases the encrypted launch input; deletion also erases that input. The receipt describes the source version used at launch, even if the desired binding changes or clears while creation is in progress. Applied means the supported creation path completed with those inputs, not that a collector accepted samples. The receipt records launch configuration rather than current collection ownership. Proxy/pull selection changes take effect against an already sampled target through their live collection paths. Changes requiring different daemon settings remain pending operator replacement of the target; start/resume does not reinject settings or silently recreate it. Source disable, credential rotation, unbinding and deletion do not revoke exporter credentials already delivered to the target.

Envd places its Device identity on every native sample. For these managed launches that identity is the Service Environment ID; native typed queries use `device_id` directly. Resource attributes additionally provide correlation without requiring the query backend to promote them into per-sample labels. Pull/proxy pipelines use the Service Environment label. Administrator mapping labels still describe operator-owned routing or relabeling.

## Optional pull collectors

Deployment settings optionally configure `vmagent` and `alloy`. Each adapter has a shared configuration directory, a reload HTTP endpoint, optional protected reload headers and an explicit `writer` flag. Reloads follow the deployment endpoint policy. An explicit `allow_http_reload` exception permits only that collector's HTTP origin for reload requests, preserving target/query policy and other HTTP restrictions; the chart enables it for its Pod-loopback vmagent. Alloy also names an existing receiver expression. The Helm chart optionally installs vmagent, disabled by default; existing external vmagent and Alloy installations remain supported. Service supplies no time-series database or query engine. Operators own backend installation, network reachability, TLS trust stores, export destinations and retention. A workspace source selects one configured collector; its delivery pipeline remains operator-owned.

The Helm-managed collector uses one dedicated `control` process co-located with vmagent in a single-replica Deployment using `Recreate`. It has its own component selector, no public Service membership and no autoscaler; both HTTP listeners bind to Pod loopback. The full control process retains normal background work and dependency requirements. Both containers run with the same non-root UID so vmagent can read protected scrape credentials. A retained POSIX-capable PVC holds the shared fragment directory and bounded forwarding queue. Startup clears stale scrape jobs under the writer lock while preserving its inode and pending queue; discovery repopulates current targets. Disabling the managed collector removes both processes, while retaining its PVC. Forced Pod replacement on an unreachable node requires operator fencing; `Recreate` and file locks are not cross-node storage fencing.

Managed Helm mode owns the vmagent collector map and enables monitoring on its Service replicas, with only the dedicated process configured as writer. External collector mode leaves adapter configuration to the operator. Remote-write credentials are mounted only into vmagent; deployment query credentials are separately provided to the API-serving control replicas. The convenience Prometheus URL derives the receiver's `/api/v1/write` path; an explicit remote-write URL overrides it. The query API base is independent and never implies a compatible ingestion receiver.

Exactly one `all` or `control` process is configured as writer per collector. Read replicas advertise the same collector settings with `writer=false`. The writer and collector share a directory with POSIX advisory-lock and atomic-rename semantics; overlapping writer replacements share that directory too. A nonblocking file lock covers discovery, replacement and the reload request. File operations run off the event loop; cancellation joins in-flight file work before releasing the lock. No database session spans route discovery, file I/O or HTTP.

The writer resolves a bounded set of current pull selections, discovers existing HTTP routes and credentials, and rechecks collection settings and target inputs before publication. It admits the first `monitoring.collector_targets` ready, supported Environment IDs per collector, default 512, and reports capacity for eligible targets beyond that limit. Non-ready targets, unsupported recipes and disabled providers do not consume collection slots. Each selection pass examines at most four times the target limit in ID order, including unsupported and failed selections; a lookahead row detects remaining inventory. Reaching the scan or target limit with more inventory sets the receipt's `truncated` flag. Eight discoveries run concurrently under the per-request deadline. External HTTP and managed Docker/E2B `envd_http` targets are supported. Unsupported, unavailable, disabled, deleted and changed targets are omitted on reconciliation rather than collected through another path. Changes after the final recheck converge on the next pass; collector requests already in flight may finish.

Only `a13n-managed.yml` (vmagent) or `a13n-managed.alloy` (Alloy) is replaced, with mode 0600 before credentials are written. vmagent's operator configuration includes that file through `scrape_config_files`; Alloy loads its configuration directory. Existing jobs, receiver definitions, remote-write flags and export credentials are untouched. Each target has its own scrape job, listener Bearer credential, additional route headers, TLS verification policy and correlation labels. Credentials never enter discovery labels or public status. The collector is trusted infrastructure because the listener credential also authorizes EIP access. Custom process-local TLS contexts are not portable collector inputs.

`POST /-/reload` asks the collector to read the shared file. It does not upload configuration. A successful response is exposed as `reload_requested`, not proof of application, scraping or export: vmagent reloads asynchronously. Target selection and discovery failures are isolated from healthy targets and reported as `discovery_failed`. Writer setup, file publication and reload failures produce a `failed` receipt and never switch to proxy. The writer retries through the next reconciliation; its bounded secret-free receipt expires in Redis after three reconciliation intervals. No current receipt means pending. Configuration removal, stopping the writer or disabling global monitoring stops reconciliation; operators remove the fragment and reload the collector to retire previously submitted jobs. Source disablement or unbinding while the writer runs removes jobs on its next successful pass.

`GET /metrics-data-sources/capabilities` reports collector configuration availability without exposing paths, endpoints or credentials. Missing collector configuration disables that option in selection interfaces. Persisted source definitions can remain configured while infrastructure is unavailable. `GET /environments/{environment_id}/metrics/collector` independently authorizes the private Environment and returns current configuration, target-discovery or reload-request status. Receipt revisions fence status after selection changes. Collector status and external historical-query results remain independent; old backend samples do not establish current reachability.

## Proxy collection and temporary history

The `all` and `control` roles collect explicitly selected, enabled proxy sources independently of Runs and browser requests. External HTTP targets and managed Docker/E2B `envd_http` targets read the existing Device descriptor and cached `device.metrics`. Managed attachment reuses target ownership, current route and protected listener-credential discovery. Credential discovery may use a bounded vendor command. Each proxy entry retains at most one protected listener credential for its current selection, physical target and validated endpoint; every attachment still checks provider ownership, current routing and endpoint policy. Failed observations clear that credential, and the next scheduled poll discovers it again without retrying the failed observation. Metric values come exclusively from Envd's sampler. Collection opens no execution Session and performs no target lifecycle operation. Unsupported providers remain unsupported.

Only ready Environments with a supported target are admitted to proxy collection; losing eligibility releases the slot and lease. Each admitted Environment connection has one temporary collection owner. The identity is the authorized Environment association, not a remote endpoint's self-reported Device ID: independent private registrations cannot merge caches by claiming the same ID. Shared thread mounts of one Environment reuse its collection. Redis holds expiring random ownership tokens and routes bounded request/reply messages between control replicas. Token-checked renewal runs independently of polling. A lost token fences subsequent cache reads and exports; Redis loss makes temporary monitoring unavailable and may discard history. PostgreSQL retains binding and credential authority. A database error pauses observations, queries and exports that require that authority, marks the entry offline and clears cached attachment credentials. An existing entry and reverse carrier can remain for at most three poll intervals from the first failed authority check, while Redis ownership is still verified. Successful authority resolution clears this grace; expiry, invalid configuration, revocation or ownership loss retires the entry. Retained history never substitutes for current authorization. No sample history is stored in Redis or PostgreSQL.

Each poll resolves current source and target inputs in a short database scope, then performs Device I/O outside it. Publication rechecks the selected source, collection/export configuration and credentials, connection inputs and ownership. Resource names and query-only settings do not invalidate the collection stream. Changed collection inputs replace the local stream and discard queued exports under the former selection. An OTLP request already sent when ownership or configuration changes may complete; delivery is best effort, not exactly once across owner loss.

Proxy admission defaults to 64 Environment connections per control process, with a maximum configuration of 512. Eight polls run concurrently, each with `monitoring.request_seconds`; selection scans are bounded and rotate through IDs. Native, pull and external queries consume none of these slots. The per-connection viewing buffer retains 24 hours of minute-aggregated overview gauges: CPU, system and cgroup memory, platform-specific memory/swap/commit, system process/thread/handle counts, cgroup PIDs, TCP/UDP counts and daemon usage. Per-interface network byte rates and per-device disk/cgroup I/O byte and operation rates retain one hour, with at most 64 sources of each kind including disappeared sources awaiting expiry. Numeric history storage is bounded below 2 MiB per connection at full inventory; source objects, the latest EIP snapshot and export state consume additional memory. Operators size admission capacity for their inventory and use an external query backend for longer resource history.

Missing samples remain gaps, stale samples are not added, repeated generation/sequence pairs are not counted twice, and generation changes start new segments. Rates use differences of counters over Host monotonic receive time corrected by sample age. Generation changes, source replacement, counter decreases, missing values, failed observations and excessive gaps interrupt continuity; the next observation establishes a baseline rather than inventing a rate. Resource identity remains on each series; network interfaces and stacked disks are never blindly summed. Disappeared sources expire or yield their bounded slots to current sources; inventory truncation and omitted source counts are explicit. Actual coverage is returned; restart and ownership changes may lose it.

Proxy export supports OTLP HTTP/protobuf. A single process queue holds at most 128 encoded observations, each at most 1 MiB, with a 32 MiB aggregate payload budget including in-flight requests, and the selected source's write destination and credential. Up to eight requests run concurrently, at most two per destination endpoint; queued items for a busy destination do not block other destinations. The upstream OTel encoder supplies the wire format; Service's async outbound client owns endpoint/TLS policy, deadlines and redirect refusal. There is no ambient exporter destination or credential fallback. Full queues, invalidated selections, failed/partial responses and shutdown discard samples with observable counters. Each Environment's temporary result exposes only its own export counts and last success, independently of local history. Export failure neither blocks collection nor changes source selection.

Proxy projection preserves the EIP 0.3 resource catalog's units, gauge/counter kinds and bounded source labels, including network, disk, cgroup I/O, socket counts, daemon usage and discovered filesystems. Native source identity distinguishes replaced interfaces and devices. Cumulative export starts reset on generation changes, counter decreases and disappearance from an exported observation. Only the current observation's counter keys are retained, so historical source churn does not grow baseline state indefinitely. Missing resource values remain absent; discovered filesystems use the same `auto:` label namespace as native exposition.

Typed Environment queries use `history=configured` by default: proxy sources without an external query return temporary history, and other configured query capabilities use their backend. `history=temporary` explicitly selects a proxy source's viewing buffer even when it also has an external query. The temporary result contains freshness, retention, actual coverage and labelled series for the requested metric. Each point is a compact tuple of Unix-second timestamp, query-local contiguous segment, sample-weighted average and peak. Resolution is at least one minute; larger requested steps are rounded up to whole minutes and aggregate only contiguous samples within the same generation. Gaps split segments even inside a coarse bucket. No finer-step interpolation or synthetic zero is returned. Overview and resource histories expose their different retention periods.

The cache owner filters and downsamples before serialization and cross-replica transport. Freshness metadata is returned by default; `include_snapshot=true` additionally returns the latest EIP sample and system information for an overview or inventory view, avoiding a full snapshot per chart. Typed external rate queries use five-minute PromQL `rate` windows and preserve native resource identities. They use the external backend's counter semantics rather than claiming identical estimates to the temporary two-observation rate. Cross-replica reads first authorize the Environment at the API boundary, then revalidate the selected stream and owner before returning data. An unavailable owner is reported explicitly; no external-query failure silently substitutes temporary history.

## Reverse monitoring Devices

A monitoring Device registration (`dev_`) is a workspace-owned association with an expected native Device identity. It is independent of Environment instances: registration creates no executable target, mount, provider handle or lifecycle operation. Administrators create, edit, disable, delete and rotate registrations; workspace readers can inspect their secret-free metadata and typed metrics. Native Device identity is immutable and unique within the workspace, which admits at most 512 registrations. A registration selects one same-workspace source or NULL. Selecting a pull source is refused because a reverse carrier supplies no collector-reachable HTTP endpoint. If a referenced source later changes to pull, its reverse carriers retire and typed Device queries report an incompatible source until an administrator selects a compatible one. Native/external ingestion remains operator-managed and its historical queries need no connected carrier.

Creation and credential rotation return a dedicated random attachment token once, with `Cache-Control: no-store`. PostgreSQL stores only its digest. Metadata reads, audit payloads and errors expose neither token nor digest. Conditional mutations use the resource ETag. Source deletion is refused while Device references remain. The Device token authenticates only the reverse carrier; it grants no human API, workspace or Run authority.

The API-serving roles admit `GET /api/v1/devices/{device_id}/connect` as a WebSocket upgrade. Admission requires the registration's Bearer credential, an enabled proxy selection, WSS (or direct loopback development WS explicitly enabled through `monitoring.allow_loopback_ws`, which defaults to false), and the `eip.v1` subprotocol. Query parameters, browser Origins and cookie-only authentication are refused. Unconfigured, disabled and native/external selections do not open a Service proxy connection. Envd retains its own sampler configuration; Service does not inject settings into an incoming Device.

The receiving replica reserves the same bounded proxy slot and expiring ownership token before accepting the upgrade. Pending handshakes count toward capacity. The shared EIP client verifies the expected identity under `monitoring.request_seconds`, using no execution Session. The supplied server limits WebSocket messages to 1 MiB and queues to eight, with compression disabled. Alternative ASGI deployments retain those carrier limits.

The socket owner also owns collection and temporary history. Other replicas route authorized typed queries to that owner; they never acquire a socket-less collection lease. Registration/source eligibility and credential changes are checked during polling and independent ownership renewal. Rotation, disablement, unbinding, deletion, workspace archival, lost ownership and unavailable authority retire the carrier; reconnecting requires fresh admission. Connection closure releases its cache and lease. Redis and process restart may lose history, and already-dispatched OTLP delivery retains the proxy best-effort boundary.

`POST /devices/{device_id}/metrics/query` uses the same typed range and explicit temporary/configured history selection as Environment queries. Proxy exports and queries use `device_registration_id`, not `environment_id`; native/external queries use the administrator-approved native `device_id`. A remote self-reported identity never merges independent authorization domains. Device management and monitoring queries are excluded from Agent tools and MCP.

## Historical query boundary

`POST /metrics-data-sources/{source_id}/query` accepts a discriminated instant or range PromQL request. It requires current workspace administration authority independently of any Environment permission. A range supplies Unix-second `start`, `end` and `step`; an instant optionally supplies `time`. The query endpoint preserves the Prometheus result envelope, including matrix, vector, scalar and string results, sample strings such as `NaN`, native histograms, warnings and informational annotations.

`POST /environments/{environment_id}/metrics/query` accepts a typed metric key and range. It authorizes workspace read and the private Environment's owner/admin boundary before reading its selected source or contacting a backend. The caller cannot supply an expression or selectors. Built-in expressions use exact-match Environment identity for proxy/pull pipelines and Device identity for native/external pipelines, together with administrator-saved mapping labels and the source's scope labels. Conflicting current source and binding labels refuse the query. Source updates therefore cannot silently override an Environment mapping.

Both paths resolve encrypted query credentials within a short database scope and release that scope before HTTP. Credentials are sent only to the configured query destination. Export credentials are never used for reads. Requests use the common outbound endpoint/TLS policy, do not follow redirects, and carry a bounded backend evaluation timeout in addition to the Service's total request deadline.

Queries have a per-process concurrency budget independent of proxy collection capacity. A full budget refuses immediately with `rate_limited`; cancellation, timeout and completion release the slot. Ranges are limited to 90 days and 11,000 evaluation points per series. Backend requests limit results to 200 series; the Service independently bounds response bytes and rejects excess series. A successful empty result remains an empty result, not an unreachable Device or synthetic zero. Backend HTTP errors, malformed responses and timeouts have detached Service errors; upstream error bodies and credentials are not included in those errors. No failure silently substitutes Local Cache or another source.

## Editable dashboards

A Metrics Dashboard (`dsh_`) is a live workspace resource containing a name and a versioned JSON document. Workspace readers can discover and read dashboards; workspace writers can create, edit and delete custom dashboards. Discovery materializes one built-in Environment overview per workspace using a unique workspace index. Its panels and name are editable through the same API as custom dashboards; its identity cannot be deleted. The preset endpoint returns the current default document. Restoring defaults stages that document and saves it through the ordinary conditional update, preserving dashboard identity.

The document's `schema_version` is 1. It stores the default time range, refresh interval and up to 24 panels. Each panel has a stable document-local ID, title, description, twelve-column grid position, time-series or stat visualization, unit, legend setting and up to four queries. IDs are unique within the document. A workspace admits at most 64 custom dashboards. Documents contain presentation and query definitions, never observations or credentials. Updates require the original strong ETag, apply atomically, and preserve the resource version on a no-op. Competing saves yield a precondition failure rather than merging layouts or overwriting drafts.

Typed panel queries name a metric from the shared catalog and select configured or temporary history. They operate on the Environment or monitoring Device selected by the viewer, through its existing authorized query endpoint. PromQL panels name a data-source ID and an expression; their execution and preview require workspace administration through the data-source query endpoint independently of dashboard read or write authority. Saving a query is inert and confers no access. A reference cannot bypass workspace scope; deleted or inaccessible sources remain explicit query failures. Dashboard documents neither retain target bindings nor prevent source deletion. Local Cache supports typed queries, not arbitrary PromQL.

Dashboard endpoints are human-facing and explicitly excluded from Agent tools and MCP admission. Console retains local drafts and their original ETags through refreshes, offers save/cancel/reset, and uses one panel renderer for built-in and custom documents. Dragging and resizing edit only the draft. Viewing supports shared time selection, refresh, zoom, cursor and per-series visibility. Query failures and missing/stale/partial histories remain visible instead of becoming zero-valued samples. Query scheduling is bounded and deduplicates identical requests; changing the target or range cancels obsolete work. Historical zoom stays pinned until the viewer returns to live mode.
