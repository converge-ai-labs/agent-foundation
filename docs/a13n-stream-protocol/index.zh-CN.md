\*\*Stream Protocol（流式协议）\*\*负责将 Harness 底层的执行观测（Observations）无缝转化为符合 AG-UI 开放规范的强类型标准事件。它在后端智能体计算循环与前端富交互界面之间搭建起高保真桥梁，提供毫秒级逐字打字效果、思维链推理分段、工具调用生命周期以及结构化结果推送。

## 从这里开始

如果您正在开发交互式聊天界面、监控大屏或桌面客户端，建议按以下路线逐步集成：

1. [Stream Protocol 快速入门](getting-started.md)：将一个活跃的 Harness 运行实例连接到 `AgUiStreamObserver` 并接收翻译后的标准 AG-UI 事件。
2. [事件类型参考](events.md)：全面查阅流式事件类型全集（文本片段、深度思考过程、工具调用与生命周期状态切换）。
3. [重放与容灾](replay.md)：基于事件序号从检查点快速重放历史流，帮助网络断线重连的前端客户端迅速补全状态。
4. [API 参考手册](api-reference.md)：查阅底层 Pydantic 事件模型定义、序列化签名与格式约束。

| 核心里程碑         | 您将实现的内容     | 校验标准                                                   |
| :----------------- | :----------------- | :--------------------------------------------------------- |
| **基础文本流**     | 单轮智能体对话推流 | 前端平滑接收并渲染 `RUN_START`、`TEXT_DELTA` 与 `RUN_END`  |
| **工具进度时间轴** | 函数调用过程可视化 | 准确呈现 `TOOL_CALL_START`、入参流式拼接与 `TOOL_CALL_END` |
| **断点恢复重放**   | 浏览器断线重连     | 从指定的任意事件序号（`seq`）瞬间重放后续未达事件          |

## 安装

Stream Protocol 作为独立包 `a13n-stream-protocol` 发布：

```bash
uv add a13n-stream-protocol
```

Stream Protocol 要求与 `a13n-harness` 保持完全一致的发布版本号，以确保底层数据结构二进制级的 100% 兼容。

## 一个 observer 对应一次执行

在 Stream Protocol 架构中，观察者对象与单次运行严格生命周期绑定：每次逻辑 Run 均应创建独立的 observer 实例。它在初始化时附加到该轮执行流上，严格按照单调递增的序列号输出事件，并在任务达到终态时优雅关闭。

## 职责归属

Stream Protocol 在执行逻辑与前端传输之间保持了清晰的系统架构边界：

| 架构层级                   | 核心职责                                                                |
| :------------------------- | :---------------------------------------------------------------------- |
| **Harness 核心引擎**       | 执行智能体决策循环、调用模型并调度各项工具                              |
| **Stream Protocol 转换层** | 拦截内部原始观测事件并将其规范转换为标准的 AG-UI 事件对象               |
| **宿主传输层**             | 负责将事件序列化并通过 Server-Sent Events (SSE)、WebSocket 或 gRPC 推送 |
| **前端交互客户端**         | 解析数据流并渲染排版、思考过程抽屉面板及代码 Diff 差异                  |

## 升级到 AG-UI 1.0

若您正在从早期协议版本升级，请重点关注 AG-UI 1.0 带来的架构演进：

- **统一的增量流格式：** 最终文本、中间思维链思考过程与工具调用入参均采用统一规范的增量片段（Delta）推流。
- **严格单调递增序列号：** 每个外发事件均携带自增的 `seq` 计数器，方便前端进行乱序重排与丢包校验。
- **清晰的多智能体归属：** 子智能体所产生的事件携带明确的父级执行追踪标识，简化嵌套多智能体协作界面的渲染。
