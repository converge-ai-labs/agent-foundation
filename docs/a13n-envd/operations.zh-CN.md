为每个工作范围打开一个会话，读取所需输出，并在该范围结束时关闭会话。会话管理自己的命令、传输、保留输出和操作历史。一个守护进程可服务多个会话；启动者管理守护进程的生命周期。

## 确认就绪

1. 创建私有运行时的父目录，并配置[守护进程](configuration.md)：设备身份、默认工作目录、可执行文件策略、限制和传输通道。
2. 启动守护进程并初始化设备连接。初始化返回设备描述符，不打开会话。
3. 检查描述符中的方法和边界。如果需要选择工作目录，先浏览设备目录。
4. 使用选定的工作目录和必需方法打开会话，等待就绪后再分派工作。
5. 将设备代次、会话身份和操作回执一同保存，让后续读取和结果核对能定位同一份工作。

工作范围存续期间，通过会话保活维持所有权。空闲 TTL 默认为 30 分钟；请使用连接所声明的空闲期限和断线宽限期。重新附加到同一会话需要显式操作，并且必须在期限内、处于同一代次。仅重新连接传输通道不会恢复会话或进行中的操作。

工作范围结束时关闭会话。清理会保留其他会话和工作区文件。会话接纳和设备总配额限制并发；清理失败的资源在确认回收前仍占用容量。

工作目录提供默认路径。访问其他设备路径的权限由执行账号和 Sandbox 授权决定。彼此不信任的工作负载应使用独立的外层账号、容器或沙箱；参见[执行边界](isolation.md)。

[Python EIP 客户端](python-client.md)提供限定范围的会话管理和方法表。客户端与守护进程的超时需要分别配置。

## 守护进程启动前规划输出容量

按并发命令规划输出容量，而不只看展示给用户的文本量。独立守护进程的默认值如下：

| 限制                  | 默认值  |
| --------------------- | ------- |
| 内联预览              | 2 MiB   |
| 每条 stdout/stderr 流 | 256 MiB |
| 每个会话的 spool      | 1 GiB   |
| 设备总 spool          | 4 GiB   |

每条命令在启动前为 stdout 和 stderr 预留容量。按默认值，一对活跃输出流预留 512 MiB。两对流就可能在计入额外用量前填满 1 GiB 会话 spool，保留记录还会进一步占用空间。仅缩小内联预览不会减少这份预留。

如果启动返回 busy，检查输出预留容量和保留 spool 用量。释放不再需要的观测记录、提高配额，或降低每条流的上限。保持 `spool >= 2 * per_stream` 和 `preview <= per_stream`。容量紧张时，守护进程可以回收符合条件的已完成历史；活跃工作保留其预留容量。

在启动守护进程的配置中设置这些限制。Python Local Envd 通过 Host 的[运行时字段](../environments/configuration.md)提供自己的预览和文件值默认设置。Native Docker 有独立的输出限制；显式选择 Envd 执行的 Docker 使用守护进程的限制。

## 预览、保留字节与完成状态

命令结果可能包含预览和保留字节的引用。按以下步骤收集输出：

1. 保存返回的输出引用及其范围、完成状态和截断字段。
2. 从该引用分批读取，每次使用返回的下一偏移量或游标继续读取。重复读取不会消费保留内容。
3. 同时检查生产方完成状态和保留内容末尾。命令可能在你读完保留字节前结束；仍在运行的生产方也可能在你读到当前末尾后继续追加。
4. 单独检查内容是否完整。到达 EOF 不会恢复因保留上限而省略的字节。
5. 将重要输出复制到应用管理的文件或持久日志，再通过对应的 EIP 方法释放不再需要的进程或输出观测记录。

进程检查报告状态，不会附加输出或重置保留预算。释放观测记录与终止活跃命令是不同操作。私有 spool 和活动连接是临时执行资源，不是持久化的 agent 检查点。

## 传输与结果不确定的命令

显式提交 writer 以完成文件传输，并检查提交结果。关闭或放弃 writer 会中止未完成的工作，而不是发布文件。保留操作回执，以区分未分派、已知完成和结果未知。

超时或传输断开后，在重放类别允许的范围内核对原操作。缺少确认无法确定命令或写入是否已经执行。将其作为新意图重新发起，可能重复副作用。

复用句柄前检查会话和设备代次。即使 provider 的远程目标仍存在，新代次也会使绑定旧代次的句柄和输出选择器失效。保存的 provider 状态可以识别目标，但无法重建已丢弃的输出，也不能恢复每条命令。

使用产品的 Run 中断来停止执行，使用会话关闭来结束执行范围，使用启动者的清理操作来停止其管理的守护进程。突然终止后，清理结果在获得证据前仍未确认。

## 在正确的层面排查失败

| 现象                           | 检查项                                                      |
| ------------------------------ | ----------------------------------------------------------- |
| 初始化或会话接纳返回 busy      | 设备会话容量、总配额、待完成清理和空闲过期                  |
| 缺少必需方法                   | 必需方法选择、有效执行身份和可执行文件策略                  |
| 启动命令前返回 busy 或配额错误 | 每对输出流的预留容量和保留 spool 用量                       |
| 预览不完整                     | 返回的引用与范围，以及生产方和完成状态证据                  |
| 文件系统或命令访问被拒绝       | 有效执行身份、Sandbox 授权和 [Host 外层边界](isolation.md)  |
| 命令或写入结果未知             | 原操作回执及其重放/核对类别；不要作为新意图重试             |
| 远程目标不可用                 | provider/后端访问和精确的已保存目标身份，不要回退到其他挂载 |

通过 EIP 检查就绪状态。HTTP 通道提供经过身份验证的控制和传输路由，不提供通用健康检查或浏览器端点。使用 stdio 时，将诊断信息写到协议 stdout 以外的位置。传输通道和启动设置见[配置](configuration.md)。
