通过 Console 使用团队的 agent。你需要 Console URL、账号和运行 agent 的权限。要部署 Service，请从[快速入门](get-started.md)开始。Console 与 Harness UI 工作台是独立应用。

## 登录

1. 打开管理员提供的 Console URL。
2. 登录，或接受邀请并创建账号。
3. 选择团队的工作空间。

在选定的工作空间中，**runner** 允许执行 agent，**builder** 还允许创建资源。组织或工作空间授予的角色均生效；如果需要访问权限，请联系管理员。参阅[角色](identity.md#roles)。

Console 默认跟随浏览器的首选语言；不支持时使用英语。要手动指定语言，请打开用户菜单，选择**偏好设置 → 显示语言**。选择**系统**即可重新跟随浏览器。

## 试用 agent

1. 打开 **会话 → 新建会话**，然后点击 **选择 Agent** 。
2. 发送符合 agent 用途的请求。对于通用 agent，可以试试：“把这些笔记整理成接下来的两步：草稿已完成；等待评审；计划周五发布。”
3. 查看流式回复。对话中也可以显示推理和工具调用。
4. 继续追问，例如“把第一步写得更具体些”。同一线程保留讨论历史。

稍后打开**会话**列表，选择**继续线程**。没有唯一主线程时，选择要打开的线程；按线程 ID 搜索会保留该精确目标。使用 Chat 继续对话，使用 Debug 检查执行。

## 创建线程分支

在想要继续的回复下方选择**从这里创建分支**，或在 Debug 的运行标题旁选择**创建分支**。填写新分支的第一条消息，再选择**创建分支并发送**。新分支仍属于同一会话，沿用所选轮次的 Agent 版本和运行选项。通过页面顶部切换线程；分支来源链接会返回继承历史的准确轮次。

所选轮次需要已停止执行，且你拥有运行 agent 的权限。等待中的轮次也可创建分支：新分支会拒绝待处理审批，并将未获答复的调用记为失败，原线程继续等待。失败或已取消的轮次从最后保存的状态继续。

文件环境和记忆默认共享，修改可能在两个线程中相互可见。在**环境选项**中启用**使用新环境**，会使用 Agent 已配置的默认环境，但不会复制旧文件；记忆仍共享。

## 创建自己的 agent

使用 [Agent Composer](agent-composer.md)描述想要的 agent，再检查配置方案。也可以按以下步骤手动配置。两种方式都需要工作空间的 builder 或 admin 权限：

1. 确认 **模型** 中有可用模型，或[添加模型](get-started.md#add-a-model)。
2. 打开 **Agents → 手动创建**，选择模型，并填写指令，例如“将项目笔记整理成简短、具体的后续行动”。
3. 选择 **创建 Agent**。
4. 选择 **试用 Agent**，并发送[试用 agent](#try-an-agent) 第 2 步中的请求。

修改配置后选择**保存更改**。新工作默认使用保存的版本；正在执行的工作和审批后继续的工作保留原版本。已固定版本的消息保留该选择。配置变更会创建修订版本，在 **版本** 中列出。按需添加[工具与连接](tools.md)、[skill](skills.md)或[子 agent](agents-and-runs.md#subagents)。修订版本选择请参阅 [Agent](agents-and-runs.md#agents)。

## 指导工作

- **问题与审批：** 回答问题，为审批选择**批准一次**或**拒绝**，完成所有待处理项后选择**提交回应**。完整批次被接受后，agent 才继续执行。普通消息不能解除等待。
- **引导或停止：** 有运行进行中时发送新消息，或停止当前运行。
- **文件与命令：** 在 **运行选项** 中选择环境，或将[环境模板](environments.md#templates)配置为 agent 的默认环境。
- **共享知识：** 在 agent 默认配置或会话的**记忆**控制中选择[记忆空间](memory.md#memory-spaces)。已有文件存储或记录型记忆使用[独立挂载](memory.md#mount-a-memory-on-a-thread)。

## 检查回复

在会话列表选择**检查执行**，或在对话中切换到 Debug。运行失败时，查看详情或将运行 ID 提供给管理员；参阅[故障排查](monitoring.md#troubleshoot-a-request-or-run)。

在 Debug 视图中，页头显示会话已产生的费用。点击后可按模型和按运行查看输入、缓存输入、缓存命中率、输出、首 Token 延迟（TTFT）、输出速度和费用；缓存输入包含在输入中。展开某次模型调用可查看该次调用的 TTFT 和输出速度。每个运行的**详情**展示该运行的同样数据，以及配置、执行尝试和运行谱系。

每条回复都标出其运行所用的模型和该运行的覆盖项数量。在 Chat 中选择模型，或在 Debug 中选择 **Agent** 行或**配置**，即可查看该运行实际执行的 Agent 配置：即应用了该运行覆盖项的 Agent 版本。该视图只读，覆盖项改动的每个部分标为**已覆盖**。Agent 之后的版本不会改变它。

Chat 和 Debug 都会显示发送者的当前姓名和原始提交时间。自己发送的消息带有**你**标记，服务账号带有**服务账号**标记。点击发送者姓名可查看和复制邮箱或账号 ID。排队消息、补充指令和分支继承的历史消息都保留各自的发送者。姓名和邮箱以当前资料为准。

阅读[核心概念](../overview/core-concepts.md)了解对话模型，使用 [Agent Composer](agent-composer.md)协助配置，或将[你的应用连接](connect-application.md)到同一 Service。
