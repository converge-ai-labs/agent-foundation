title: 使用已有平台
description: 在 Console 中运行团队的 agent，继续对话，并创建自己的 agent。

团队已有 Service 时，可以按本指南操作。你需要 Console URL、账号和运行 agent 的权限。接下来会发送请求、在同一线程中追问，并了解如何检查执行或创建分支。自行部署请从[快速入门](get-started.md)开始。Console 是 Service 的应用界面；Harness UI 是独立的工作台。

## 登录

1. 打开管理员提供的 Console URL。
2. 登录，或接受邀请并创建账号。
3. 选择团队的工作空间。

**runner** 可以执行 agent，**builder** 还可以创建资源。组织和工作空间授予的权限会作用于选定的工作空间。如需权限，请联系管理员；参阅[角色](identity.md#roles)。

要切换显示语言，打开用户菜单，选择**语言 → 显示语言**。**系统**跟随支持的浏览器语言，否则使用英语。选择保存在当前浏览器中。

## 试用 agent

1. 打开**会话 → 新建会话**，再选择**选择 Agent**。
2. 发送符合 agent 用途的请求。对于通用 agent，可以试试：`Turn these notes into two next steps: draft ready; review pending; release planned for Friday.`。
3. 阅读流式回复。回复旁还可能显示工具调用和推理。
4. 继续追问 `Make the first step more specific.`。同一线程会保留讨论历史。

稍后返回时，打开**会话**并选择**继续线程**。会话中有多个可能的主线程时，需要选择其中一个；按线程 ID 搜索则打开该精确目标。使用 Chat 继续对话，使用 Debug 检查执行。

## 创建线程分支

想尝试另一种方向，同时保留原对话时，可以创建分支：

1. 在回复下方选择**从这里创建分支**，或在 Debug 的运行旁选择**创建分支**。
2. 输入新分支的第一条消息，例如 `Explore a plan that postpones the release by one week.`。
3. 检查环境选项，再选择**创建分支并发送**。

分支仍属于同一会话，沿用所选运行的 agent 版本和选项。通过页头切换线程；来源链接会返回分支继承历史的准确运行。

你需要运行权限，且所选运行已停止执行。等待中的运行也能创建分支：新分支会拒绝其中待处理的审批，并将未获回答的调用记为失败，原线程继续等待。失败或取消的运行提供最后保存的检查点，因此可能不含未保存的工作。

两个线程默认共享文件环境和记忆。要使用新的文件环境，选择**环境选项 → 使用新环境**。这会使用 agent 已配置的默认环境，不复制旧文件，记忆仍然共享。

## 创建自己的 agent

拥有 builder 或 admin 权限后，可以通过 [Agent Composer](agent-composer.md)描述 agent 并检查其提出的配置方案。手动设置步骤如下：

1. 检查**模型**中是否有可用模型，或[添加模型](get-started.md#add-a-model)。
2. 打开 **Agents → 手动创建**，命名 agent，选择模型，并将 `Turn project notes into short, concrete next steps.` 填入指令。
3. 选择**创建 Agent**，再选择**试用 Agent**。
4. 发送[试用 agent](#try-an-agent)中的笔记，检查回复，并按需要调整指令。

编辑后选择**保存更改**。每次配置变更都会创建修订版本，在**版本**中列出。新工作默认使用保存的版本；正在执行的工作和审批后的继续执行保留原版本，显式固定版本的消息也保留其选择。修改应用正在使用的 agent 前，请阅读[修订版本选择](agents-and-runs.md#agents)。

随着任务需要，添加[工具](tools.md)、[skill](skills.md)或[子 agent](agents-and-runs.md#subagents)。

## 指导工作

| 情况                   | 操作                                                                                                                                                           |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| agent 提问或请求审批   | 回答每个问题，为每项审批选择**批准一次**或**拒绝**。完成所有待处理项，再选择**提交回应**。完整批次被接受后才继续执行；普通消息不能解除等待。                   |
| 需要调整正在进行的工作 | 在运行期间发送新消息，或停止当前运行。                                                                                                                         |
| 任务需要文件或命令     | 在**运行选项**中选择环境，或将[环境模板](environments.md#templates)设为 agent 的默认环境。                                                                     |
| 多个对话需要相同知识   | 在 agent 默认配置或会话的**记忆**控制中选择[记忆空间](memory.md#memory-spaces)。已有文件存储或记录型记忆使用[独立挂载](memory.md#mount-a-memory-on-a-thread)。 |

## 检查回复

在会话列表选择**检查执行**，或将对话切换到 Debug。根据要解决的问题选择入口：

| 问题                     | 查看位置                                                                                                                                                               |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 运行为什么失败？         | 打开运行详情并检查失败信息。需要时向管理员提供运行 ID；参阅[故障排查](monitoring.md#troubleshoot-a-request-or-run)。                                                   |
| 哪份配置生成了这条回复？ | 选择 Chat 中的模型，或 Debug 中的 **Agent** 或**配置**。只读视图展示该运行的 agent 版本与覆盖项合并后的配置，改动的部分标为**已覆盖**。之后编辑 agent 不会改变该视图。 |
| 对话花费了多少？         | 选择 Debug 页头的会话费用，按模型和运行查看明细。运行的**详情**展示其用量、配置、执行尝试和运行谱系。                                                                  |
| 谁发送了消息？           | 点击发送者姓名，查看或复制邮箱、账号 ID。消息显示原始提交时间和发送者当前资料。自己的消息带有**你**标记，服务账号带有**服务账号**标记。                                |

用量包括输入、缓存输入、缓存命中率、输出、首 Token 延迟（TTFT）、输出速度和费用。缓存输入包含在输入中。展开模型调用可查看该次调用的计时数据。每条回复也标出所用模型和覆盖项数量。排队消息、补充指导及分支继承的历史都保留各自的发送者。
