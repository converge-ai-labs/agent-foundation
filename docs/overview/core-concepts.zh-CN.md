通过与一个汇报项目状态的 agent 的一次对话来了解这些概念。此示例通过 **Console** 或 Service SDK 使用托管 agent 运行时 **Service**。嵌入式执行和交互式工作请参阅[选择使用方式](choose-your-path.md)。

## 选择 agent

管理员授予你某个**工作空间** 中的角色。工作空间中包含团队的 agent、其他资源和对话。你在组织和工作空间中的角色决定了可以使用或修改哪些内容。

一个 **agent** 由模型、指令和工具组成。指令示例：“总结项目进展，并引用所使用的信息”。

| 组成部分 | 在 agent 工作中的作用                         |
| -------- | --------------------------------------------- |
| **模型** | 理解请求，生成回复或工具调用                  |
| **工具** | 查找任务、读取文件或执行其他已配置的操作      |
| **连接** | 通过 MCP 或应用账号访问外部工具               |
| **环境** | 为工具提供文件访问和命令执行能力              |
| **记忆** | 保存项目决策，让 agent 在不同对话中读取和更新 |

先配置模型和指令。让 agent 查询实际进展前，先添加能读取项目数据的工具或连接。[工具与连接](../a13n-service/tools.md)介绍了配置方法。

## 开始对话

发送：“总结项目状态，并列出接下来的两个任务。”

在 Console 中选择 agent 并发送消息。在应用中使用 SDK 的高层启动操作。Service 会自动创建对话所需的资源。

回复和工具活动会随进度显示。agent 工作时，可以补充说明或停止执行。补充说明可能在下一次模型请求时生效，也可能继续排队；请查看接收状态，不要假定它已被应用。

## 回答问题或审批工具调用

如果 agent 询问你指的是哪个项目，就在问题卡片中回答。如果工具调用需要审批，明确选择批准或拒绝。完成所有待处理请求后再提交回答。完整批次被接受后，对话会继续。应用通过[等待、审批和问题](../a13n-service/agents-and-runs.md#waits-approvals-and-questions)处理这些情况。

## 稍后继续

打开**会话**列表，选择**继续对话**，再询问“我应该先做哪个任务？”。应用向返回的线程引用发送后续消息。断开连接后，工作会继续，Service 会保存历史，供你回来后继续。需要排查问题时，选择**检查执行**打开诊断视图。

| 信息     | 用途                             |
| -------- | -------------------------------- |
| 线程历史 | 继续当前线程                     |
| 记忆     | 在不同对话之间保存和检索信息     |
| 环境文件 | 保存文档和工具使用的其他工作文件 |

将[记忆](../a13n-service/memory.md)挂载到线程，或将其设为 agent 的默认挂载，即可跨对话共享保存的决策。记忆可以提供文件上下文或自动召回相关记录；启用记忆工具后，agent 可以搜索和更新记忆。[环境](../a13n-service/environments.md)模板的空闲策略决定了环境中的文件可以保留多久。

## 需要时再了解执行细节

**会话（session）** 将相关的\*\*线程（thread）**组织在一起。每个线程都有独立的历史和收件箱；分支或委派任务可以使用独立线程。一次**运行（run）**使用 agent 的模型和工具推进线程。一次**执行尝试（run attempt）\*\*记录 worker 对该运行的执行，包括恢复过程。Console 的 Debug 视图展示这些细节；普通对话操作会自动处理相关标识符。

这些对象与消息并非一一对应：补充说明可以加入正在进行的运行，回答等待中的请求则会创建后继运行。具体生命周期请参阅 [Agent、线程与运行](../a13n-service/agents-and-runs.md)。

每次保存 agent 配置都会创建不可变的**修订版本**。新运行选择当前默认版本，除非消息固定了其他版本。正在执行的工作保留已接受的配置，审批后继续的运行继承等待运行的版本。通过**版本**可以查看已保存的配置。
