# Models

List configured Models and read the selected key before changing an Agent. The model catalog is descriptive; creating or selecting a configured Model still requires an authorized Provider resource. Model settings follow the deployed Provider's calling API schema in the instance catalog. Do not invent fields.

To look up public prices and characteristics, call `get_model_catalog` with `provider` (the catalog channel, such as `openrouter`) and `model` (the exact upstream model ID). Both filters are optional, case-sensitive exact matches and combine with AND. Prefer both when known; use `view=compact`, `query`, `capability`, `limit` and `cursor` to discover model IDs when needed. For a selected provider/model, `section=all|characteristics|pricing` returns a versioned fragment (`offset`, `text_limit`, `version`). Default detailed reads retain `{items, status}`; an empty match does not mean the model is free, and `stale` or `unavailable` must be reported when relevant. Filtering does not change full-directory refreshes or cache contents.

Use the selected item's `ref.model` as `model_name`, `characteristics` as `characteristics`, `pricing` as `pricing`, and `ref` as `catalog_ref` when creating a Model with `create_model`. Choose the authorized workspace `provider_id` and its supported `model_api` separately. For an existing Model, read it first and use `update_model` with `key`, the observed `expected_version` and only intended fields; omitted configuration and user-entered values survive. Copy prices only from the requested channel; do not substitute another channel's prices. If `pricing` is null, report the missing price or `pricing_warning` instead of inventing a value. Catalog reads never save or update a Model automatically.

Model resources are shared by key. Explain the affected shared settings before updating one. To change one Agent's sampling or model behavior, prefer that Agent's `model_settings` when appropriate. Keep unrelated settings intact. Read the Model's `version` and pass `key:version` as `expected_version`. Supplied settings, characteristics, pricing and header sections replace those sections whole. Retain unrelated values within a section being replaced. Provider credentials are entered in the Console, never in chat.

Provider credentials and secret headers use the trusted Provider configuration card or Console. Internal business model tools do not configure provider secrets. Never put secret values in model configuration or ordinary header settings.

The `anthropic` Provider automatically sends its one saved API key in both `X-Api-Key` and `Authorization: Bearer`, including on connection probes and custom gateway URLs. Do not ask for or configure a separate Authorization header. Both names are reserved; remove an existing custom Authorization entry when upgrading.

Service defaults effective model settings to `cache: true` for primary and auxiliary calls. Prefer native `cache` settings for prompt caching: `false` disables library-managed caching and a retention value selects its duration. Model defaults and Agent overrides remain authoritative. For Anthropic Messages, the default also enables `anthropic_cache_instructions`, `anthropic_cache_tool_definitions` and `anthropic_cache_messages`, placing markers on content blocks instead of sending top-level `cache_control` for gateway compatibility. An explicit unified `cache` setting or any of these provider settings (including `anthropic_cache`) keeps the native authored policy. Pydantic AI owns provider-specific marker placement; provider support and repeated prefixes determine cache hits.

The `cloudflare_ai_gateway` Provider uses a Cloudflare token as its credential, `account_id` (or a custom `base_url` ending in `/ai`), and optional `gateway_id`. Use the `cloudflare-ai-gateway` catalog channel and retain publisher-prefixed model IDs. Use `openai.chat_completions` for all supported chat models; vendor-native settings are not automatically translated into gateway capabilities. A provider probe checks provider readiness; actual authorized execution is needed to establish inference access for a particular Model. Do not configure Authorization or `cf-aig-gateway-id` as extra headers; they are owned by the Provider.
