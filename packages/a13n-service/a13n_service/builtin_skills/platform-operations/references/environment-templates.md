# Environment templates

Templates describe how later Environment instances are created. Query the authorized environment Providers and use their deployed recipe schema from the instance catalog. Read the template and its ETag before updating it. A template update does not create, start or reconfigure an existing instance. Explain which future instances use it. Agent default environment selection and lazy startup have their existing lifecycle rules; preserve unrelated values. Instance start/stop/delete, shell and file access are outside this platform tool selection.

Service reads the default mount's working-directory `AGENTS.md` and discovers project-local guidance paths before inference. Child `AGENTS.md` and `.agents/skills` entries are path-only hints, not loaded bodies or additional selected Skills. The default is `workspace` when present, otherwise the sole user mount. This preparation can activate that Environment even when the model uses no tools; other mounts remain lazy unless `lazy_environment: false` requests eager instance preparation. Guidance discovery grants no additional permissions.

Native Execution provides Files & Shell through Local direct access, Docker containerization, or E2B remote sandboxes for quick deployment and basic applications. Envd is the general execution path for OS sandbox and Egress policy enforcement, Computer use, and Device metrics. Each vendor's Environment Provider retains resource management and connection preparation.

Native Docker does not expose port inspection/wait or Computer operations; select the explicit Envd route for those capabilities. Changing a template does not install Envd in an existing native container.

For Docker Computer use, select a compatible desktop variant of `a13n-sandbox` with `execution: envd_http` and `desktop: true`. The Provider's `docker_host` selects the Engine; its separate `envd_http` settings select the reachable host and port-publication interface. Service discovers the container's published EIP port and attaches to the image-managed daemon. Preserve the image's user, display, and envd settings. Configure Agent tools and mount permissions separately.

For Computer use on an E2B target, prepare a template containing compatible Envd and desktop runtimes and establish an explicit EIP connection. E2B's provider manages the sandbox and desktop resources; Native E2B execution remains Files & Shell. Check the deployed schema and negotiated EIP methods before selecting the route, then configure Agent Computer tools and mount action ceilings.

For Chinese desktop rendering, select a custom E2B desktop template with CJK fonts installed at build time (for example, `fonts-noto-cjk`). The official `desktop` template may lack these fonts; Service does not install them during connection or input. Create a new environment after selecting the custom template. Envd owns Agent text-input semantics. Confirm focus before typing, split long text, and reconcile uncertain input before continuing.

For Daytona Computer use, select a snapshot with compatible Envd, desktop packages, and required CJK fonts. The Daytona provider prepares resources and the EIP connection during create/start; execution attachment checks the retained target. Agent operations use Envd/EIP. Enable the Agent's Computer toolset and matching mount permissions separately.

For Daytona Console viewing, Agent-requested assistance and user takeover, also set `desktop_assistance: true` and select an operator-built `snapshot` that preinstalls and starts the desktop access supervisor. A default snapshot or a native signed preview URL alone does not provide the required input and revocation controls. Service reuses its safe pause, exclusive control and resume flow; input with an unknown outcome blocks handoff. Snapshot construction requires separate build authority and is not performed by template creation or runtime attachment. After a template change, create a new environment to use the snapshot.

For Modal, supply an explicit Envd-compatible registry `image` or Modal image ID (`im-...`) and an existing App. Use `desktop: true` for Computer use and also `desktop_assistance: true` for Console viewing, assistance and takeover. The image must include the shared desktop launcher and access supervisor. Agent operations use EIP on a TLS tunnel to port 8888; human grants use a separate tunnel to port 6081. Enable Agent Computer tools and mount permissions separately. Stop preserves files through a snapshot; resume changes the sandbox and desktop generation. Old native recipes and plain Python images require migration and a new environment.
