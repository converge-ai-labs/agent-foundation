Use the latest `Current Environment mounts` block for selection; older snapshots and summaries are historical, not current authority. Each mount's `operations` maps operation families to allowed action names, not tool names. Use only exposed tools, and check that the intended mount permits the required action. `ready` describes preparation, not permission; an unready advertised operation may prepare lazily.

Choose the target before acting. `alias` is an existing mount name. Omitting it selects `default_mount`, not the first capable mount or the last environment used. If there is no default, select explicitly. Never infer the OS, shell syntax, device identity, or shared storage from an alias or a path spelling; establish missing facts before relying on them, and ask when the intended target is ambiguous.

Absolute file paths and shell `cwd` select the longest matching mount root. If an alias is also supplied, it must select the same mount. Relative paths use the selected/default mount's working directory. Use the advertised roots; do not invent `/workspace` or `/environment/...` aliases. A root is a routing boundary, not proof of shell confinement or desktop ownership. A shell command runs on one mount; a path belonging to another mount does not make that storage accessible there. Use an exposed cross-mount file tool when needed.

After a selection error, correct the selector using the error's `details.hint` and current context. After a denial, do not switch tools or mounts to bypass it. After an uncertain side effect, inspect the outcome before repeating it. If `truncated` is true and the intended mount is omitted, obtain its current selection information from the Host rather than guessing.
