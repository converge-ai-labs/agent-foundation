Use `computer_describe` when targets or readiness are unclear, and `computer_observe` to inspect the intended desktop before interacting. Readiness does not grant input permission. Pointer tools use the returned `observation_id` and the configured `coordinate_space` reported with the observation. The default is `pixels`; `normalized_1000` uses relative integer positions on each axis and the tool performs the conversion. Never infer the mode from the model name. Scroll deltas retain their advertised units.

Use `computer_zoom` when a region needs more detail. It captures fresh native pixels before cropping and downsizing. Select the region in the source observation's configured coordinate space, with exclusive right/bottom edges (1000 reaches the full edge in normalized mode). The returned `region_pixels` uses source-image pixels. Zoom images are for inspection only: keep using `source_observation_id` and full-screen coordinates for pointer input, never the zoom image's local coordinates. Zoom neither creates a clickable reference nor extends the source reference's lifetime. Reobserve if the desktop changed enough to need a new overview.

`obs-` references belong to one logical Run and one mount incarnation; only the most recent 16 observations are retained. Same-Run context compaction does not itself invalidate them, but a new Run, eviction, or target replacement can. A reference remembered in a summary is not proof of validity. If unavailable or stale, capture a new image on the intended mount, reassess the GUI, and use the new reference.

Use `computer_read_clipboard` and `computer_write_clipboard` only when their independent actions are available on the intended mount. They exchange plain Unicode text up to 16384 UTF-8 bytes; CRLF becomes LF. Empty text is valid and differs from `no_content` or `no_text`. Reads fail rather than truncate. Writes replace shared clipboard content; they do not paste or save/restore it. Copy/read and write/paste are separate, racing operations: a key receipt does not prove an application published or inserted text. Keep these workflows in the same live Session; X11 ownership ends when its Session closes, and no platform promises persistence across restart or human handoff. After partial/unknown publication or incomplete `cleanup_complete`, reconcile before further mutation and never automatically replay a write.

An observation binds geometry, not screen freshness or foreground focus. Other users and agents may change the shared GUI. Text and keys affect current foreground focus, not a named window. `effect=executed` means input was posted, not that the application accepted it. `input_cleanup_complete` reports whether the operation released its own pressed keys/buttons. Partial or unknown effects are not replay-safe. If cleanup is incomplete, stop further input and ask the Host to reconcile input state; a screenshot alone cannot prove keys/buttons were released. Observe current state before deciding what to do next; never blindly repeat input after a timeout or uncertain result.
