Use `computer_describe` when targets or readiness are unclear, and `computer_observe` to inspect the intended desktop before interacting. Readiness does not grant input permission. Pointer tools use the returned `observation_id` and image pixel coordinates.

`obs-` references belong to one logical Run and one mount incarnation; only the most recent 16 observations are retained. Same-Run context compaction does not itself invalidate them, but a new Run, eviction, or target replacement can. A reference remembered in a summary is not proof of validity. If unavailable or stale, capture a new image on the intended mount, reassess the GUI, and use the new reference.

An observation binds geometry, not screen freshness or foreground focus. Other users and agents may change the shared GUI. Text and keys affect current foreground focus, not a named window. `effect=executed` means input was posted, not that the application accepted it. `input_cleanup_complete` reports whether the operation released its own pressed keys/buttons. Partial or unknown effects are not replay-safe. If cleanup is incomplete, stop further input and ask the Host to reconcile input state; a screenshot alone cannot prove keys/buttons were released. Observe current state before deciding what to do next; never blindly repeat input after a timeout or uncertain result.
